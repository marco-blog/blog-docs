# Feature Specification: 포털 (주제별 글 모아보기와 메인)

**Feature Branch**: `003-portal`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "사람들이 작성한 글을 활용해 티스토리처럼 포털을 만든다. 서비스 공통 주제별로 글을 볼 수 있어야 한다. 주제는 티스토리 주제 분류를 그대로 미리 정해 둔다. 글 작성 시 블로그 카테고리는 선택할 수도, 안 할 수도 있다."

> 요구사항 번호는 이전 스펙에서 이어진다. FR-034, FR-075~080은 포털을 분리하기 전의 002 스펙(당시 구독·탐색·포털을 함께 다룸)에서 옮겨 왔고 FR-085부터 새로 추가했다. 지금의 002-discovery-feeds에는 이 번호가 없다.

## 개념 정리

| 구분 | 블로그 카테고리 | 서비스 주제 |
|---|---|---|
| 누가 만드나 | 블로그 주인이 자유롭게 (티스토리도 동일) | 운영자가 미리 정한 목록, 티스토리 주제 분류를 따름 |
| 어디에 쓰이나 | 블로그 안의 글 분류, 블로그 사이드바 | 포털의 주제별 목록 |
| 글당 개수 | 0~1개(미선택 = 미분류) | 0~1개(미선택 = 포털 "전체"에만) |
| 구조 | 상위·하위 2단계 | 대분류·소분류 2단계 |
| 예 | "Spring 공부", "일상 기록" | 지식·동향 > IT 인터넷, 여행·맛집 > 국내여행 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 포털 메인에서 글 둘러보기 (Priority: P1)

방문자가 `blog.java21.net`에 들어오면 여러 블로그의 글을 모은 포털 메인을 본다. 메인에는 운영자 추천 글, 주제 탭(대분류), 지금 인기 있는 글, 최신 글, 인기 태그가 있고, 글 카드를 누르면 해당 블로그의 글로 이동한다.

**Why this priority**: 서비스의 첫 화면이며 새 독자가 들어오는 주 경로다.

**Independent Test**: 여러 블로그에 주제·이미지가 다른 공개 글 30편을 만든 뒤 메인을 열어 각 영역에 조건에 맞는 글만 나오고, 로그아웃 상태에서 스크립트 없이 요청해도 글 목록이 HTML에 들어 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 방문자, **When** 메인을 열면, **Then** 위에서부터 운영자 추천, 주제 탭(대분류), 인기 글, 최신 글, 인기 태그, 새로 시작한 블로그 영역이 보인다.
2. **Given** 글 카드, **When** 방문자가 보면, **Then** 대표 이미지(없으면 기본 이미지), 제목, 요약 2줄, 블로그 이름, 글쓴이 프로필 이미지, 발행 시각(예: "3시간 전"), 좋아요·댓글 수가 보인다.
3. **Given** 인기 글 영역, **When** 메인을 열면, **Then** 최근 7일 인기 점수 상위 글이 보이고, 한 블로그의 글은 최대 2편까지만 나온다.
4. **Given** 최신 글 영역, **When** "더 보기"를 누르면, **Then** 다음 20편이 이어서 나온다.
5. **Given** 포털 노출 조건을 만족하지 않는 글(FR-088), **When** 메인을 보면, **Then** 그 글은 어느 영역에도 나오지 않는다.

### User Story 2 - 주제별로 글 보기 (Priority: P2)

방문자는 주제 탭(대분류)이나 주제 페이지(예: `blog.java21.net/topics/knowledge/it-internet`)에서 그 주제의 글만 최신순·인기순으로 본다.

**Why this priority**: 관심 분야의 글만 골라 보는 포털의 핵심 탐색 방식이다.

**Independent Test**: 주제 "IT 인터넷" 글 3편(블로그 A 2편, B 1편), "모바일" 글 1편, 주제 없는 글 1편 발행 → "IT 인터넷" 페이지에 3편, "지식·동향" 페이지에 4편만 나오고 정렬을 바꾸면 순서가 바뀌는지 확인. 자동 숨김(FR-147)은 주제 페이지에 영향을 주지 않으며, 주제 탭까지 확인할 때는 테스트 설정에서 자동 숨김 기준(프로퍼티)을 1편으로 낮춘다.

**Acceptance Scenarios**:

1. **Given** 방문자, **When** 주제 탭에서 "지식·동향"을 누르면, **Then** 대분류 페이지로 이동해 소분류 목록과 소속 글이 최신순으로 20편씩 보이고, 소분류 "IT 인터넷"을 누르면 그 글만 보인다.
2. **Given** 주제 페이지, **When** 정렬을 "인기순"으로 바꾸면, **Then** 최근 7일 인기 점수 순으로 바뀐다.
3. **Given** 주제 페이지, **When** 검색 엔진이 요청하면, **Then** 주제 이름이 들어간 제목과 설명, 글 목록이 HTML에 포함된다.
4. **Given** 운영자가 숨긴 주제의 주소, **When** 방문자가 접속하면, **Then** "찾을 수 없음" 화면이 나온다. 글이 적어 주제 탭에서 자동으로 숨겨진 주제(FR-147)의 주소는 정상으로 열린다.

### User Story 3 - 글에 주제 지정하기 (Priority: P3)

글쓴이는 글을 쓸 때 블로그 카테고리와 별개로 서비스 주제를 하나 고를 수 있다(선택 사항). 블로그 기본 주제를 정해 두면 새 글에 미리 선택된다. 포털에 글을 내보내고 싶지 않으면 블로그 단위로 끌 수 있다.

**Why this priority**: 포털에 글이 들어오는 입구다. 주제를 고르지 않아도 글쓰기는 막히지 않는다.

**Independent Test**: 블로그 기본 주제를 "국내여행"으로 설정 → 새 글 작성 화면에 "국내여행"이 미리 선택됨 → 주제를 "선택 안 함"으로 바꿔 발행 → 포털 "국내여행" 페이지에는 없고 최신 글에는 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 글 작성 화면, **When** 회원이 보면, **Then** "카테고리"(내 블로그 분류, 선택)와 "주제"(포털 분류, 선택)가 따로 있다.
2. **Given** 주제를 고르지 않은 글, **When** 발행하면, **Then** 정상 발행되고 포털 최신 글에는 나오지만 주제 페이지에는 나오지 않는다.
3. **Given** 블로그 기본 주제 "국내여행", **When** 새 글을 쓰면, **Then** 주제에 "국내여행"이 미리 선택되어 있고 바꿀 수 있다.
4. **Given** 블로그 설정에서 "포털에 내 글 노출"을 끈 블로그, **When** 글을 발행하면, **Then** 블로그·RSS에는 나오지만 포털 어디에도 나오지 않는다.
5. **Given** 이미 발행한 글, **When** 주제를 바꾸면, **Then** 포털의 주제 목록에 바로 반영된다.

### User Story 4 - 운영자 큐레이션과 주제 관리 (Priority: P4)

운영자는 포털 메인 상단에 보여줄 추천 글을 고르고 노출 기간을 정한다. 주제 목록을 추가·이름 변경·순서 변경·숨김하고, 부적절한 글을 포털에서만 내릴 수 있다.

**Why this priority**: 포털 품질을 사람이 관리하는 수단이다. 자동 목록만으로도 포털은 동작하므로 마지막 순서다.

**Independent Test**: 관리자가 글 3편을 추천으로 지정(종료일 내일) → 메인 상단에 지정 순서대로 나옴 → 종료일이 지나면 사라지는지, 포털 제외한 글이 메인·주제 페이지에서 사라지지만 블로그에는 남는지 확인.

**Acceptance Scenarios**:

1. **Given** 관리자, **When** 공개 글을 추천으로 지정하고 노출 시작·종료 시각과 순서를 정하면, **Then** 그 기간 동안 메인 상단 추천 영역에 순서대로 보인다.
2. **Given** 추천 글이 비공개·삭제되거나 포털 노출 조건을 잃으면, **When** 메인을 열면, **Then** 추천 영역에서 자동으로 빠진다.
3. **Given** 관리자, **When** 주제를 추가·이름 변경·순서 변경·숨김하면, **Then** 메인 주제 탭(대분류)과 글 작성 화면에 반영된다.
4. **Given** 관리자, **When** 특정 글을 "포털에서 제외"하면, **Then** 포털 모든 영역에서 빠지지만 블로그·검색·RSS에서는 그대로 보인다.
5. **Given** 추천 영역이 비어 있는 기간, **When** 메인을 열면, **Then** 추천 영역 없이 다음 영역부터 보인다.

### User Story 5 - 서비스 업데이트 소식(릴리스 노트) 읽기 (Priority: P5)

회원과 방문자는 서비스가 새 버전으로 바뀌면 무엇이 달라졌는지 읽는다. 포털 메인과 상단 배너가 새 버전을 알려 주고, `/updates`에서는 모든 버전의 릴리스 노트를 위키처럼 버전 트리·목차·검색으로 찾아 읽는다. 릴리스 노트는 시스템 관리자가 관리자 콘솔에서 쓰고 게시하며(006 FR-167·168), 회원과 방문자는 읽기만 한다.

**Why this priority**: 서비스 변화를 이용자에게 알리는 창구다. 포털의 글 탐색 기능과는 독립적이며 없어도 포털은 동작한다.

**Independent Test**: 관리자가 v1.2.0(한국어·영어판), v1.2.1(한국어판만), v1.3.0을 차례로 게시 → 비로그인으로 포털 메인에 v1.3.0 카드가 보이는지, `/updates`에 "1.3"·"1.2" 묶음 트리가 보이고 `/updates/v1.2.0#…` 앵커 주소로 그 절이 바로 열리는지 확인. 화면 언어를 일본어로 바꾸면 v1.2.0은 영어판, v1.2.1은 한국어판으로 보이는지 확인. 회원으로 로그인해 상단 배너를 닫은 뒤 다른 기기에서 로그인해도 배너가 다시 나오지 않는지 확인.

**Acceptance Scenarios**:

1. **Given** 게시 후 14일이 지나지 않은 최신 릴리스 노트, **When** 방문자가 포털 메인을 열면, **Then** 맨 위에 그 버전·제목 카드가 보이고 누르면 `/updates/v{버전}`으로 이동한다. 14일이 지나면 카드는 보이지 않는다.
2. **Given** 마지막으로 확인한 버전보다 새 버전이 게시된 상태의 회원, **When** 서비스 화면을 열면, **Then** 상단에 새 버전을 알리는 한 줄 배너가 보이고, 닫거나 그 버전의 노트를 열면 이후 어느 기기에서도 그 버전의 배너가 다시 보이지 않는다.
3. **Given** `/updates`, **When** 방문자가 열면, **Then** 왼쪽에 major.minor로 묶은 버전 트리, 오른쪽에 최신 버전 본문과 본문 제목으로 만든 목차가 보이고, 트리에서 다른 버전을 누르면 그 버전의 고유 주소로 바뀐다.
4. **Given** 버전 페이지, **When** 목차의 항목을 누르거나 앵커가 붙은 주소(`/updates/v1.2.0#새-기능`)로 들어오면, **Then** 그 절로 바로 이동하고, 페이지 아래의 이전·다음 버전 링크로 이웃 버전으로 갈 수 있다.
5. **Given** `/updates`의 검색창, **When** 키워드를 넣으면, **Then** 게시된 노트 중 화면 언어(언어판이 없으면 대체 언어판)의 제목·본문에 키워드가 있는 버전이 일치 부분과 함께 나온다.
6. **Given** 게시 후 관리자가 수정한 노트, **When** 독자가 버전 페이지의 "수정 이력"을 열면, **Then** 수정 시각 목록이 보이고 각 이전 수정본의 내용을 볼 수 있다.
7. **Given** 초안(DRAFT) 상태의 노트, **When** 관리자가 아닌 사람이 그 버전 주소로 들어가면, **Then** "찾을 수 없음" 화면이 나온다.

### Edge Cases

- 글이 거의 없는 초기에는 각 영역이 비어 있을 수 있다. 빈 영역은 숨기고, 메인 전체가 비면 "첫 글을 써 보세요" 안내를 보여준다.
- 같은 블로그가 짧은 시간에 글을 대량 발행해도 메인 인기 글·최신 글 한 화면에 그 블로그 글이 2편을 넘지 않는다.
- 가입 직후 계정이 스팸 글을 대량 발행하는 경우를 막기 위해 가입 후 24시간이 지나지 않은 회원의 글은 포털에 나오지 않는다(블로그에는 보인다).
- 본문이 너무 짧은 글(텍스트 200자 미만)은 포털에 나오지 않는다.
- 글이 포털 노출 조건을 잃으면(비공개 전환, 삭제, 숨김, 회원 정지) 다음 포털 갱신 때 모든 영역에서 빠진다.
- 운영자가 숨긴 주제의 글은 주제 페이지에는 나오지 않지만 메인 최신·인기 글에는 나올 수 있다.
- 글이 적어 자동으로 숨겨진 주제(FR-147)는 주제 탭에서만 빠진다. 글쓰기 화면에서 계속 고를 수 있고 주제 페이지도 열리므로, 글이 쌓이면 기준을 넘어 탭에 다시 나타난다.
- 대표 이미지가 없는 글은 기본 이미지(주제별 색상)로 카드를 그린다.
- 게시된 릴리스 노트가 하나도 없으면 `/updates`는 "아직 업데이트 소식이 없습니다" 안내를 보여주고, 포털 카드와 배너는 나오지 않는다.
- 관리자가 게시한 노트를 초안으로 되돌리면(게시 중단, 006 FR-167) 그 버전 주소는 "찾을 수 없음"이 되고, 포털 카드·배너는 남은 게시 노트 중 최신 버전 기준으로 다시 정해진다.
- 회원의 화면 언어판이 없는 노트는 영어판, 영어판도 없으면 한국어판으로 보이며, 어느 언어판인지 본문 위에 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

**포털 메인**

- **FR-034**: 서비스 메인(`blog.java21.net/`)은 포털이며, 운영자 추천, 주제 탭(대분류), 인기 글, 최신 글, 인기 태그, 새로 시작한 블로그 영역을 이 순서로 보여야 한다. 내용이 없는 영역은 숨긴다. 게시 14일 이내의 최신 릴리스 노트가 있으면 이 영역들보다 위에 릴리스 노트 카드를 보여준다(FR-162).
- **FR-085**: 글 카드는 대표 이미지(없으면 기본 이미지), 제목, 요약 2줄, 블로그 이름, 글쓴이 프로필 이미지, 상대 시각, 좋아요 수, 댓글 수를 보여야 한다.
- **FR-086**: 인기 점수는 최근 7일 신호로 계산하고 오래된 글일수록 낮아져야 한다. 클릭(조회) 수만으로 정하지 않는다. 내부 글은 끝까지 읽은 비율(본문 끝 도달)과 좋아요·댓글을 조회 수보다 크게 반영하고, 신고가 인정되었거나 숨김 처리된 이력이 있는 블로그는 점수를 낮춘다. 정확한 가중치는 계획 단계에서 정하고 운영자가 바꿀 수 있어야 한다. 예외: 외부 블로그 글(007)은 우리 서비스에서 읽음·좋아요·댓글을 잴 수 없으므로 007 FR-124(포털 카드 클릭 수 + 운영자 가중치)로 점수를 낸다. 001 research R10의 `views + likes*10` 공식은 이 FR로 대체되었다.
- **FR-147**: 포털 주제 탭은 최근 30일 포털 노출 글(외부 글(007) 포함)이 기준(기본 20편) 미만인 주제를 자동으로 숨겨야 한다(자동 숨김). 자동 숨김은 주제 탭에만 적용되며, 그 주제는 글쓰기 화면에서 계속 고를 수 있고 주제 페이지도 "찾을 수 없음"이 되지 않는다(운영자 숨김 FR-079와 다름). 운영자는 기준과 관계없이 탭에 열어 둘 주제를 직접 지정할 수 있다(출시 초기에는 IT·개발 관련 소분류부터 연다). 기준은 운영 설정 프로퍼티로 바꿀 수 있으며 테스트에서는 낮춰서 쓴다.
- **FR-087**: 메인의 인기 글은 12편, 최신 글은 처음 20편과 "더 보기"(20편씩), 인기 태그는 최근 7일 사용 수 상위 20개, 새로 시작한 블로그는 최근 30일 안에 첫 글을 발행한 블로그 6개를 보여야 한다.
- **FR-080**: 메인의 각 영역에서 같은 블로그 글은 최대 2편까지만 노출한다.

**포털 노출 조건**

- **FR-088**: 포털(메인, 주제 페이지, 인기 태그)에 나오는 글은 "본문 노출 가능"(001 FR-018, 001 data-model 글 노출 매트릭스. 보호 글은 제외) 조건에 더해 다음을 모두 만족해야 한다: 블로그의 포털 노출 설정이 켜져 있음, 운영자가 포털에서 제외하지 않음, 글쓴이 가입 후 24시간 경과(블로그를 만든 시각이 아니라 회원 가입 시각 기준, 001 FR-010), 본문 텍스트 200자 이상. 조건값(24시간, 200자)은 운영자가 바꿀 수 있어야 한다. 외부 블로그 글(007)에는 이 조건 대신 007 FR-123을 적용한다(FR-080·FR-093은 적용, 가입 24시간·200자 조건은 적용하지 않음).
- **FR-089**: 블로그 주인은 "포털에 내 글 노출"을 끌 수 있어야 한다(기본 켜짐). 꺼도 블로그, 검색, RSS에는 영향이 없다.
- **FR-090**: 포털 목록은 글의 상태 변화(발행, 수정, 비공개 전환, 삭제, 숨김)를 5분 이내에 반영해야 한다.

**주제**

- **FR-075**: 서비스는 운영자가 관리하는 2단계(대분류·소분류) "주제" 목록을 미리 정해 두어야 한다. 초기 목록은 티스토리 주제 분류를 따른다(아래 표, 출시 전 티스토리 현행 목록과 대조해 확정). 각 주제는 주소용 영문 식별자(예: `it-internet`)를 가진다.

  | 대분류 | 소분류 |
  |---|---|
  | 라이프 | 일상·생각, 육아·결혼, 반려동물, 패션·뷰티, 인테리어·DIY, 요리·레시피, 상품리뷰, 원예·재배 |
  | 여행·맛집 | 국내여행, 해외여행, 캠핑·등산, 맛집, 카페·디저트 |
  | 문화·연예 | TV, 스타, 영화, 음악, 책, 만화·애니, 공연·전시·축제, 창작 |
  | 스포츠 | 축구, 야구, 농구, 배구, 골프, 일반 스포츠 |
  | 지식·동향 | IT 인터넷, 모바일, 과학, IT 제품리뷰, 경영·직장, 경제, 사회, 정치, 교육, 건강·의학, 역사, 외국어 |

  위 표는 한국어 이름만 적었다. FR-079에 따라 영어·일본어·중국어(간체) 이름을 출시 전 목록 확정 때 함께 채운다.
- **FR-076**: 글 작성·수정 시 주제는 선택 사항이며 한 글에 소분류 하나만 고를 수 있다. 블로그 카테고리 선택과는 독립적이다.
- **FR-077**: 블로그 주인은 블로그 기본 주제를 정할 수 있고, 새 글 작성 시 기본값으로 미리 선택된다.
- **FR-078**: 대분류 페이지(`blog.java21.net/topics/{대분류식별자}`)는 소속 소분류 글을 모두, 소분류 페이지(`blog.java21.net/topics/{대분류식별자}/{소분류식별자}`)는 그 소분류 글만 최신순·인기순으로 한 페이지 20편씩 보여야 한다. 주제가 없는 글은 주제 페이지에 나오지 않는다.
- **FR-079**: 관리자는 대분류·소분류를 추가·이름 변경·순서 변경·숨김할 수 있어야 한다. 주제는 삭제하지 않고 숨기며, 운영자가 숨긴 주제(운영자 숨김)는 작성 화면에서 고를 수 없고 주제 탭(대분류)에 나오지 않으며 주제 페이지는 "찾을 수 없음"이 된다. 대분류를 숨기면 소분류도 함께 숨겨진다. 주제 식별자는 만든 뒤 바꿀 수 없다. 주제 이름은 4개 언어로 입력해야 한다(001 FR-151).

**운영자 큐레이션**

- **FR-091**: 관리자는 공개 글을 메인 추천으로 지정하고 노출 시작·종료 시각과 순서를 정할 수 있어야 한다. 동시에 노출되는 추천은 최대 5편이다.
- **FR-092**: 추천 글이 포털 노출 조건을 잃으면 추천 영역에서 자동으로 빠져야 한다.
- **FR-093**: 관리자는 특정 글을 포털에서 제외하거나 제외를 풀 수 있어야 하며, 제외는 블로그·검색·RSS 노출에는 영향을 주지 않는다. 제외 사유를 기록한다.

**노출과 검색 엔진**

- **FR-094**: 포털 메인과 주제 페이지는 스크립트 없이 요청해도 글 목록과 페이지 제목·설명·공유 미리보기 정보를 포함해야 한다. 주제 페이지는 사이트맵에 포함한다.
- **FR-095**: 포털 상단에는 검색창(002 검색 사용)과 로그인 상태에 따라 로그인·가입 또는 글쓰기·내 블로그 링크가 있어야 한다.

**릴리스 노트(서비스 업데이트 소식)**

- **FR-161**: 서비스 릴리스 노트는 시스템 관리자가 관리자 콘솔에서 쓰고 게시한다(006 FR-167·168). 회원과 방문자는 게시(PUBLISHED)된 노트를 읽기만 할 수 있으며, 초안(DRAFT)은 관리자 외의 사람에게 "찾을 수 없음"으로 응답한다. 노트는 화면 언어판으로 보여주고, 그 언어판이 없으면 영어판, 영어판도 없으면 한국어판(필수)을 보여주며 어느 언어판인지 표시한다. 본문 Markdown은 글 본문과 같은 변환·위험 요소 제거 과정(001 FR-021, FR-083, FR-140)을 거쳐 보여준다.
- **FR-162**: 포털 메인은 가장 최근에 게시된 노트가 게시 후 14일(운영 설정 프로퍼티) 이내이면 다른 영역보다 위에 그 버전·제목 카드를 보여야 하며, 카드를 누르면 그 버전의 페이지(`/updates/v{버전}`)로 이동한다.
- **FR-163**: 로그인한 회원에게는 회원별로 저장한 "마지막으로 확인한 버전"보다 새 버전의 노트가 게시되어 있으면 서비스 공통 상단에 한 줄 배너(새 버전 번호·제목·보기 링크)를 보여야 한다. 회원이 배너를 닫거나 그 버전 페이지를 열면 마지막 확인 버전을 그 버전으로 저장하고, 이후 어느 기기에서도 그 버전 이하의 배너를 보여주지 않는다. 회원 가입 시각보다 먼저 게시된 노트는 배너로 알리지 않는다. 비로그인 방문자에게는 배너가 없다.
- **FR-164**: `/updates`는 릴리스 노트를 위키 형태로 보여야 한다. 왼쪽은 게시된 버전을 major.minor 묶음(예: "1.2" 아래 1.2.0·1.2.1)으로 묶은 트리(새 버전이 위), 오른쪽은 고른 버전의 본문과 본문 제목으로 자동 만든 목차다. `/updates`는 최신 버전을 보여주고, 각 버전은 바뀌지 않는 고유 주소(`/updates/v1.2.0`)를 가지며, 본문의 제목마다 앵커(`/updates/v1.2.0#새-기능`)가 있어 절 단위로 연결할 수 있다. 버전 페이지 아래에 이전·다음 버전 링크를 두고, 본문에서 다른 버전 주소로 링크할 수 있다. 버전 페이지는 스크립트 없이 요청해도 본문과 제목·설명 메타 정보를 포함해야 한다(FR-094와 같은 기준).
- **FR-165**: `/updates`의 검색창은 게시된 노트의 제목·본문을 화면 언어(그 언어판이 없는 노트는 FR-161의 대체 언어판)로 검색해 버전·제목·일치 부분을 새 버전부터 보여야 한다.
- **FR-166**: 게시 후 수정된 노트의 버전 페이지는 "수정 이력"을 보여야 한다. 독자는 처음 게시한 때부터의 수정본 목록(수정본 번호, 수정 시각)과 각 수정본의 내용을 볼 수 있다. 수정한 관리자는 독자에게 보이지 않으며, 게시 전 초안 단계의 수정본은 관리자 콘솔에서만 볼 수 있다(006 FR-168).

### Key Entities *(include if feature involves data)*

- **주제(Topic)**: 4개 언어 이름(ko, en, ja, zh-CN), 영문 식별자, 상위 주제(대분류), 순서, 운영자 숨김 여부, 운영자가 열어 둔 주제 여부. 자동 숨김(FR-147)은 저장값이 아니라 최근 30일 글 수로 계산한다. 서비스 전체 공통 2단계. 글과 블로그 기본 주제는 소분류만 가리키며 0~1개.
- **블로그 포털 설정**: 포털 노출 여부, 기본 주제.
- **추천(Curation)**: 글, 노출 시작·종료 시각, 순서, 지정한 관리자.
- **포털 제외(Portal exclusion)**: 글, 사유, 처리한 관리자, 시각.
- **포털 설정값**: 인기 점수 가중치(외부 글 가중치 포함, 007 FR-124), 신규 회원 노출 대기 시간, 최소 본문 길이, 주제 자동 숨김 기준.
- **릴리스 노트(Release note)**: 버전, 릴리스 날짜, 언어별 제목·본문, 상태(초안/게시), 게시 시각, 수정본. 관리자 콘솔에서 만든다(006 Key Entities). 이 스펙은 읽기만 한다.
- **회원의 마지막 확인 버전**: 회원마다 마지막으로 확인(배너 닫기·버전 페이지 열기)한 릴리스 노트 버전 하나(FR-163).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-023**: 포털 주제 탭에 글이 거의 없는(최근 30일 20편 미만) 주제가 나타나는 경우가 0건이다.
- **SC-011**: 방문자는 포털 메인에서 원하는 주제의 글 목록까지 클릭 한 번으로 이동할 수 있다.
- **SC-012**: 포털 메인과 주제 페이지는 95%의 요청에서 1초 안에 글 목록을 보여준다(SC-003 규모 기준).
- **SC-013**: 비공개 전환·삭제·숨김·포털 제외된 글은 5분 안에 포털 모든 영역에서 사라진다.
- **SC-014**: 포털 메인 한 화면(각 영역)에 같은 블로그 글이 2편을 넘는 경우가 0건이다.
- **SC-004**: 001 SC-004를 따른다(포털 모든 영역 포함. 보호 글은 포털에 나오지 않는다).

## Assumptions

- 001-blog-core와 002-discovery-feeds가 구현되어 있다고 가정한다(좋아요 수, 조회 통계, 검색을 사용).
- 개인화 추천(관심 주제 선택, 읽은 글 기반 추천), 광고 영역, 배너 관리, 실시간 인기 검색어는 이번 범위 밖이다. 릴리스 노트 배너(FR-163)는 운영자가 따로 관리하는 배너가 아니라 게시된 노트에서 자동으로 나오는 알림이다.
- 릴리스 노트의 작성·수정·게시와 수정본 보관은 006(FR-167·168)이, 독자 화면(포털 카드, 상단 배너, `/updates`)은 이 스펙이 정한다. `blog-docs/release-notes/` 폴더는 관리자가 붙여 넣을 원고(초안)를 Claude가 쓰는 곳이며 이용자에게 보이는 원본은 DB의 게시본이다.
- 로그인한 회원의 구독 피드는 002의 별도 화면(`/feed`)이며, 포털 메인에는 "구독 피드 보기" 링크만 둔다.
- 운영자 기능 화면은 006의 시스템 관리자 콘솔 안에 들어간다. 이 스펙은 기능 요구만 정의한다.
- 서비스 이름과 기본 이미지 디자인은 별도로 정한다.
