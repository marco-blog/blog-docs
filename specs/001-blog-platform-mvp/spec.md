# Feature Specification: 멀티 유저 블로그 플랫폼 MVP

**Feature Branch**: `001-blog-platform-mvp`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "티스토리 같은 멀티 유저 블로그 플랫폼. 트랙백·RSS 같은 블로그 고유 기능 포함. 누구나 가입하면 자신의 블로그를 갖고 글을 쓰며, 다른 사람은 공개 글을 읽고 댓글·좋아요·구독을 한다. 토큰 기반 인증(Access 30분, Refresh 4시간)."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입하고 내 블로그에 글 쓰기 (Priority: P1)

방문자가 회원가입을 하면 자기 블로그 주소(handle)를 가진 블로그가 바로 생긴다. 로그인한 뒤 글을 써서 발행하면, 로그인하지 않은 방문자도 블로그 홈과 글 상세에서 그 글을 읽을 수 있다.

**Why this priority**: 블로그 서비스의 존재 이유다. 이것만 있어도 "글을 쓰고 공유하는" 최소 가치가 생긴다.

**Independent Test**: 새 계정으로 가입 → 로그인 → 글 1편 발행 → 로그아웃 상태에서 블로그 홈과 글 상세 주소로 접속해 본문이 보이는지 확인.

**Acceptance Scenarios**:

1. **Given** 처음 온 방문자, **When** 이메일·비밀번호·닉네임·블로그 주소를 입력해 가입하면, **Then** 계정과 블로그가 함께 생기고 블로그 홈이 비어 있는 상태로 열린다.
2. **Given** 이미 사용 중인 이메일이나 블로그 주소, **When** 가입을 시도하면, **Then** 어느 항목이 중복인지 알려주고 가입되지 않는다.
3. **Given** 가입한 회원, **When** 올바른 이메일과 비밀번호로 로그인하면, **Then** 로그인 상태가 되고 30분 동안 다시 로그인하지 않아도 된다.
4. **Given** 로그인 후 30분이 지났지만 4시간은 지나지 않은 회원, **When** 계속 서비스를 이용하면, **Then** 다시 로그인하라는 요청 없이 로그인 상태가 이어진다.
5. **Given** 마지막 로그인(또는 로그인 연장) 후 4시간이 지난 회원, **When** 로그인이 필요한 기능을 쓰면, **Then** 다시 로그인하라는 안내를 받는다.
6. **Given** 로그인한 회원, **When** 제목과 본문을 쓰고 "공개"로 발행하면, **Then** 자기 블로그 홈 목록 맨 위에 글이 나타나고 고유 주소로 상세를 볼 수 있다.
7. **Given** 발행된 공개 글, **When** 로그인하지 않은 방문자가 글 주소로 접속하면, **Then** 제목·본문·작성자·작성일이 보인다.
8. **Given** 회원이 "비공개"로 저장한 글, **When** 다른 사람이 그 글 주소로 접속하면, **Then** "존재하지 않는 글"과 같은 응답을 받는다.
9. **Given** 자기 글, **When** 수정하거나 삭제하면, **Then** 수정 내용이 바로 반영되고 삭제한 글은 누구에게도 보이지 않는다.
10. **Given** 다른 사람의 글, **When** 수정·삭제를 시도하면, **Then** 거부된다.

### User Story 2 - 카테고리와 태그로 글 정리하기 (Priority: P2)

블로그 주인은 자기 블로그의 카테고리를 만들고 글을 분류하며, 글에 태그를 단다. 방문자는 카테고리나 태그를 눌러 관련 글만 모아 본다.

**Why this priority**: 글이 쌓이면 정리 수단이 없을 때 블로그를 읽기 어려워진다. 티스토리의 핵심 탐색 방식이다.

**Independent Test**: 카테고리 2개(상위·하위) 생성 → 글 3편을 서로 다른 카테고리·태그로 발행 → 카테고리/태그별 목록에 해당 글만 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 상위 카테고리와 그 아래 하위 카테고리를 만들면, **Then** 블로그 사이드 영역에 계층 구조로 표시된다.
2. **Given** 카테고리에 속한 글이 있는 상태, **When** 그 카테고리를 삭제하면, **Then** 글은 삭제되지 않고 "미분류"로 옮겨진다.
3. **Given** 글 작성 중, **When** 태그를 최대 10개까지 입력하면, **Then** 글 상세에 태그가 표시되고 11번째 태그는 추가되지 않는다.
4. **Given** 방문자, **When** 카테고리나 태그를 누르면, **Then** 해당하는 공개 글만 최신순으로 보인다.

---

### User Story 3 - 댓글로 소통하기 (Priority: P3)

로그인한 회원은 공개 글에 댓글과 대댓글을 달고, 글 주인은 자기 글의 댓글을 관리한다.

**Why this priority**: 블로그가 "여러 사람이 쓰는" 서비스가 되는 첫 상호작용이다.

**Independent Test**: 회원 A의 글에 회원 B가 댓글, A가 대댓글 → 두 댓글이 계층으로 보이고, A가 B의 댓글을 삭제할 수 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 공개 글에 댓글을 쓰면, **Then** 글 아래에 작성자·작성 시각과 함께 표시된다.
2. **Given** 기존 댓글, **When** 그 댓글에 답글을 달면, **Then** 원 댓글 아래 한 단계 들여쓰기로 표시되고, 답글에 다시 답글을 달 수는 없다.
3. **Given** 댓글 작성자, **When** 자기 댓글을 수정·삭제하면, **Then** 반영된다.
4. **Given** 글 주인, **When** 자기 글에 달린 다른 사람의 댓글을 삭제하면, **Then** 삭제된다.
5. **Given** 로그인하지 않은 방문자, **When** 댓글을 쓰려 하면, **Then** 로그인 안내를 받는다.

---

### User Story 4 - 좋아요, 구독, 구독 피드 (Priority: P4)

회원은 마음에 드는 글에 좋아요를 누르고, 다른 블로그를 구독해 구독한 블로그들의 새 글을 한 곳에서 본다.

**Why this priority**: 재방문을 만드는 기능이지만, 글·댓글이 먼저 있어야 의미가 있다.

**Independent Test**: 회원 B가 회원 A의 블로그를 구독 → A가 새 글 발행 → B의 구독 피드 맨 위에 그 글이 보이는지, 좋아요 수가 1 늘어나는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 글의 좋아요를 누르면, **Then** 좋아요 수가 1 늘고, 다시 누르면 취소되어 1 줄어든다.
2. **Given** 로그인한 회원, **When** 다른 블로그를 구독하면, **Then** 그 블로그의 구독자 수가 1 늘어난다.
3. **Given** 회원, **When** 자기 블로그를 구독하려 하면, **Then** 구독 버튼이 보이지 않거나 거부된다.
4. **Given** 구독 중인 블로그의 새 공개 글, **When** 구독 피드를 열면, **Then** 구독한 블로그들의 공개 글이 최신순으로 보인다.

---

### User Story 5 - 둘러보기와 검색 (Priority: P5)

방문자는 메인 페이지에서 최신 글과 인기 글을 보고, 키워드로 전체 글을 검색한다. 공개 글은 검색 엔진에도 노출된다.

**Why this priority**: 새 독자 유입 경로다. 콘텐츠가 어느 정도 쌓인 뒤에 가치가 커진다.

**Independent Test**: 공개 글 여러 편과 비공개 글 1편을 만든 뒤, 메인·검색 결과에 공개 글만 나오는지, 검색 엔진 크롤러처럼 스크립트 없이 요청해도 본문이 포함되는지 확인.

**Acceptance Scenarios**:

1. **Given** 방문자, **When** 메인 페이지를 열면, **Then** 서비스 전체의 최신 공개 글과 최근 7일 인기 글이 보인다.
2. **Given** 방문자, **When** 키워드로 검색하면, **Then** 제목·본문·태그에 키워드가 들어간 공개 글이 나온다.
3. **Given** 비공개 또는 삭제된 글, **When** 어떤 목록·검색·피드를 보더라도, **Then** 그 글은 나타나지 않는다.
4. **Given** 공개 글 상세 페이지, **When** 스크립트를 실행하지 않는 클라이언트가 요청하면, **Then** 응답에 제목·본문·요약 설명이 포함되어 있다.

---

### User Story 6 - 글에 이미지 넣기 (Priority: P6)

회원은 글 작성 중 이미지를 올려 본문에 넣는다.

**Why this priority**: 블로그 글에 흔히 필요하지만, 텍스트만으로도 앞의 이야기들은 동작한다.

**Independent Test**: 글 작성 화면에서 이미지 1장 업로드 → 본문에 삽입 → 발행 후 방문자 화면에서 이미지가 보이는지 확인.

**Acceptance Scenarios**:

1. **Given** 글 작성 중인 회원, **When** 10MB 이하의 jpg·png·gif·webp 이미지를 올리면, **Then** 본문에 이미지가 삽입된다.
2. **Given** 10MB를 넘거나 이미지가 아닌 파일, **When** 업로드하면, **Then** 이유와 함께 거부된다.
3. **Given** 이미지를 올렸지만 글을 저장하지 않고 떠난 회원, **When** 24시간이 지나면, **Then** 그 이미지는 삭제되어 더 이상 열리지 않는다.
4. **Given** 이미지가 들어간 글, **When** 글을 수정해 이미지를 본문에서 지우고 저장하면, **Then** 그 이미지는 정리되어 삭제된다.

---

### User Story 7 - 신고와 운영 (Priority: P7)

회원은 부적절한 글이나 댓글을 신고하고, 관리자는 신고를 검토해 콘텐츠를 숨기거나 사용자를 정지한다.

**Why this priority**: 여러 사람이 쓰는 서비스에 필요하지만 초기 사용자 규모에서는 가장 나중에 필요하다.

**Independent Test**: 회원이 글 신고 → 관리자가 신고 목록에서 해당 글 숨김 → 방문자에게 그 글이 보이지 않는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 다른 사람의 글이나 댓글을 사유를 골라 신고하면, **Then** 신고가 접수된다.
2. **Given** 관리자, **When** 신고된 콘텐츠를 숨김 처리하면, **Then** 작성자 외 누구에게도 보이지 않는다.
3. **Given** 관리자, **When** 사용자를 정지하면, **Then** 그 사용자는 로그인할 수 없고 블로그 방문 시 "이용이 제한된 블로그" 안내가 보인다.
4. **Given** 관리자가 아닌 회원, **When** 관리 화면에 접근하면, **Then** 거부된다.

---

### User Story 8 - RSS·Atom 피드로 블로그 구독하기 (Priority: P8)

독자는 이 서비스에 가입하지 않고도 RSS 리더(피드리, 이노리더 등)에 블로그 주소를 넣어 새 글을 받아 본다. 블로그 주인은 피드에 전문을 넣을지 요약만 넣을지, 몇 개를 넣을지 정한다.

**Why this priority**: 블로그를 블로그답게 만드는 표준 기능이다. 서비스 밖의 독자를 붙잡는 유일한 수단이다.

**Independent Test**: 블로그에 공개 글 3편과 비공개 글 1편 작성 → RSS 리더나 피드 검증기로 블로그 피드 주소 확인 → 공개 글 3편만, 설정한 형태(전문/요약)로 들어 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 공개 글이 있는 블로그, **When** 블로그 피드 주소(RSS 2.0, Atom 1.0)를 요청하면, **Then** 최신 공개 글이 최신순으로 표준 형식에 맞게 들어 있다.
2. **Given** 블로그 주인이 피드 공개 범위를 "요약"으로 설정, **When** 피드를 요청하면, **Then** 각 글은 본문 대신 요약만 담는다.
3. **Given** 카테고리가 있는 블로그, **When** 카테고리 피드 주소를 요청하면, **Then** 그 카테고리의 공개 글만 담긴다.
4. **Given** 블로그 홈이나 글 상세 페이지, **When** 브라우저나 RSS 리더가 페이지를 읽으면, **Then** 페이지가 피드 주소를 자동 발견할 수 있게 알려준다.
5. **Given** 비공개·보호·삭제·숨김 글, **When** 어떤 피드를 요청하더라도, **Then** 그 글은 들어 있지 않다.

---

### User Story 9 - 트랙백 주고받기 (Priority: P9)

다른 블로그의 글을 참고해 글을 쓴 사람은 원글에 트랙백을 보내 "이 글을 참고한 글이 있다"고 알린다. 원글 아래에는 받은 트랙백 목록이 표시되어 블로그 사이의 글이 서로 연결된다.

**Why this priority**: 블로그 사이를 잇는 블로그 고유의 기능이다. 다른 서비스 블로그와도 표준 방식으로 주고받는다.

**Independent Test**: 블로그 A의 글 주소에 표준 트랙백 핑을 보냄 → A의 글 아래 트랙백(보낸 글 제목·요약·블로그 이름·링크)이 보이는지 확인. 반대로 블로그 B에서 글을 발행하며 A의 글 트랙백 주소를 입력 → A의 글에 트랙백이 생기는지 확인.

**Acceptance Scenarios**:

1. **Given** 트랙백을 허용한 블로그의 공개 글, **When** 외부 블로그가 그 글의 트랙백 주소로 표준 트랙백 핑을 보내면, **Then** 글 아래 트랙백 목록에 보낸 글의 제목·요약·블로그 이름·주소가 추가되고, 보낸 쪽에는 성공 응답이 간다.
2. **Given** 글 작성 중인 회원, **When** 보낼 트랙백 주소를 입력하고 발행하면, **Then** 그 주소로 트랙백 핑이 전송되고 성공·실패 결과가 글 관리 화면에 표시된다.
3. **Given** 트랙백을 막아둔 블로그 또는 비공개 글, **When** 트랙백 핑이 오면, **Then** 거부 응답을 보내고 저장하지 않는다.
4. **Given** 받은 트랙백, **When** 글 주인이 삭제하면, **Then** 목록에서 사라진다.
5. **Given** 같은 주소에서 짧은 시간에 반복해서 오는 핑, **When** 제한을 넘으면, **Then** 거부되어 스팸이 쌓이지 않는다.
6. **Given** 글 상세 페이지, **When** 방문자가 보면, **Then** 이 글의 트랙백 주소가 표시되어 복사할 수 있다.

---

### User Story 10 - 방명록 (Priority: P10)

방문자는 특정 글이 아니라 블로그 자체에 인사나 메시지를 남긴다. 블로그 주인은 답글을 달고 관리한다.

**Why this priority**: 티스토리 블로그의 대표적인 소통 공간이지만 글·댓글이 먼저다.

**Independent Test**: 회원 B가 회원 A의 블로그 방명록에 글을 남김 → A가 답글 → 방명록 화면에 두 글이 계층으로 보이는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 다른 블로그의 방명록에 글을 남기면, **Then** 방명록 최상단에 표시된다.
2. **Given** 방명록 글을 쓸 때 "비밀글"을 선택, **When** 다른 방문자가 보면, **Then** 내용 대신 "비밀글입니다"가 보이고 블로그 주인과 작성자만 내용을 본다.
3. **Given** 블로그 주인, **When** 방명록 글에 답글을 달거나 삭제하면, **Then** 반영된다.
4. **Given** 방명록을 꺼둔 블로그, **When** 방문자가 방명록에 접근하면, **Then** 방명록 메뉴가 보이지 않는다.

---

### User Story 11 - 블로그 꾸미기와 탐색 도구 (Priority: P11)

블로그 주인은 공지사항을 올리고, 블로그 사이드바에 보여줄 항목(최근 글, 최근 댓글, 인기 글, 태그 목록, 월별 보관함, 방문자 수)을 고른다. 방문자는 월별 보관함과 관련 글로 지난 글을 찾아 읽는다.

**Why this priority**: 블로그를 "개인 공간"답게 만드는 기능들이다. 핵심 흐름이 갖춰진 뒤에 붙인다.

**Independent Test**: 공지 1편 등록, 사이드바에 방문자 수·월별 보관함·태그 목록 켜기 → 방문자 화면에 공지가 목록 위에 고정되고, 선택한 사이드바 항목만 보이며, 보관함에서 특정 달을 누르면 그 달의 글만 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 글을 공지로 지정하면, **Then** 블로그 홈 글 목록 위에 공지가 따로 표시되고 일반 목록에는 섞이지 않는다.
2. **Given** 블로그 주인, **When** 사이드바 항목을 켜고 끄고 순서를 바꾸면, **Then** 방문자 화면 사이드바에 그대로 반영된다.
3. **Given** 방문자, **When** 월별 보관함에서 특정 달을 누르면, **Then** 그 달에 발행된 공개 글만 보인다.
4. **Given** 방문자 수 항목을 켠 블로그, **When** 방문자가 블로그를 보면, **Then** 오늘·어제·전체 방문자 수가 보인다.
5. **Given** 글 상세, **When** 방문자가 끝까지 읽으면, **Then** 같은 카테고리나 태그가 겹치는 관련 글 최대 5편이 보인다.
6. **Given** 글 상세, **When** 방문자가 공유를 누르면, **Then** 글 주소를 복사하거나 주요 SNS로 공유할 수 있다.

### User Story 12 - 글 공개 옵션 확장 (Priority: P12)

블로그 주인은 비밀번호를 아는 사람만 읽는 보호 글을 쓰고, 정한 시각에 자동 발행되도록 예약한다. 댓글 작성자는 글 주인만 보는 비밀 댓글을 남기고, 블로그 주인이 허용하면 로그인하지 않은 방문자도 이름과 비밀번호로 댓글을 단다.

**Why this priority**: 티스토리에서 자주 쓰는 글·댓글 옵션이지만, 기본 공개/비공개만으로도 앞의 흐름은 동작한다.

**Independent Test**: 보호 글 작성 → 다른 계정에서 비밀번호 없이 본문이 안 보이고 비밀번호 입력 후 보이는지 확인. 10분 뒤로 예약한 글이 그 전엔 안 보이고 그 후엔 목록에 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 보호 글, **When** 방문자가 열면, **Then** 제목과 비밀번호 입력란만 보이고, 맞는 비밀번호를 넣으면 본문이 보인다.
2. **Given** 보호 글, **When** 목록·피드·검색에 나올 때, **Then** 제목만 나오고 본문·요약은 나오지 않는다.
3. **Given** 예약 발행으로 저장한 글, **When** 예약 시각 전에 방문자가 접근하면, **Then** 보이지 않고, 예약 시각이 지나면 자동으로 발행되어 목록·피드에 나온다.
4. **Given** 댓글 작성 시 "비밀 댓글"을 선택, **When** 다른 방문자가 보면, **Then** "비밀 댓글입니다"만 보이고 글 주인과 작성자만 내용을 본다.
5. **Given** 비회원 댓글을 허용한 블로그, **When** 로그인하지 않은 방문자가 이름·비밀번호·내용을 입력하면, **Then** 댓글이 등록되고 같은 비밀번호로만 수정·삭제할 수 있다.
6. **Given** 비회원 댓글을 허용하지 않은 블로그, **When** 로그인하지 않은 방문자가 댓글을 쓰려 하면, **Then** 로그인 안내를 받는다.

### Edge Cases

- 블로그 주소에 대문자, 공백, 특수문자, 예약어(admin, api, login, search 등 서비스 페이지 경로)를 쓰면 가입이 거부된다.
- 나중에 서비스 페이지 경로를 새로 추가할 때 이미 같은 이름의 블로그가 있으면 그 경로를 쓸 수 없다(새 경로는 예약어 목록과 기존 블로그 주소를 먼저 확인).
- 같은 사람이 짧은 시간에 같은 글을 여러 번 열어도 조회수는 한 번만 오른다.
- 본문이나 댓글에 스크립트를 넣어도 다른 사람의 화면에서 실행되지 않는다.
- 로그인 비밀번호를 연속으로 여러 번 틀리면 일정 시간 로그인이 제한된다.
- 글을 삭제하면 그 글의 댓글과 좋아요도 함께 보이지 않는다.
- 로그아웃하면 그 기기의 로그인 연장 수단도 즉시 무효가 된다.
- 탈퇴한 회원의 글은 즉시 비공개가 된다.
- 존재하지 않는 블로그 주소나 글 주소로 접속하면 "찾을 수 없음" 화면이 나온다.

- 트랙백 핑에 들어온 제목·요약에 스크립트가 있어도 실행되지 않는다.
- 이미 받은 것과 같은 주소의 트랙백이 다시 오면 새로 쌓지 않는다.
- 트랙백을 보낼 주소가 응답하지 않으면 정해진 시간 안에 실패로 기록하고 글 발행은 그대로 완료된다.
- 보호 글의 비밀번호를 여러 번 틀리면 일정 시간 시도가 제한된다.
- 예약 시각을 과거로 지정하면 즉시 발행된다.
- 같은 방문자가 하루에 여러 번 블로그에 들어와도 방문자 수는 하루 한 번만 오른다.

## Requirements *(mandatory)*

### Functional Requirements

**계정과 인증**

- **FR-001**: 방문자는 이메일, 비밀번호, 닉네임, 블로그 주소로 회원가입할 수 있어야 한다. 이메일과 블로그 주소는 서비스 전체에서 유일해야 한다.
- **FR-002**: 블로그 주소는 영문 소문자·숫자·하이픈으로 된 3~20자여야 하며, 가입 후 바꿀 수 없다. 블로그 주소가 서비스 최상위 경로를 그대로 쓰므로, 서비스 자체 페이지와 겹치는 이름(예: admin, api, login, signup, logout, search, tags, feed, write, manage, settings, notifications, sitemap, rss, static, assets, help, about)은 예약어로 막아야 한다.
- **FR-003**: 비밀번호는 8자 이상이고 영문과 숫자를 모두 포함해야 하며, 원문 그대로 저장하지 않는다.
- **FR-004**: 회원은 이메일과 비밀번호로 로그인하고 로그아웃할 수 있어야 한다.
- **FR-005**: 로그인 후 발급되는 접근 자격은 30분간 유효해야 하고, 로그인 연장 자격은 4시간간 유효해야 한다. 연장 자격이 유효한 동안은 다시 로그인하지 않고 접근 자격을 새로 받을 수 있어야 한다.
- **FR-006**: 로그아웃하면 그 로그인의 연장 자격은 즉시 무효가 되어야 한다.
- **FR-007**: 같은 계정으로 로그인에 5회 연속 실패하면 10분간 로그인이 제한되어야 한다.
- **FR-008**: 회원은 닉네임, 소개, 프로필 이미지를 수정할 수 있어야 한다.
- **FR-009**: 회원은 탈퇴할 수 있으며, 탈퇴하면 로그인할 수 없고 그 회원의 글은 즉시 비공개가 되어야 한다.

**블로그**

- **FR-010**: 회원 1명은 블로그 1개를 가지며, 가입과 동시에 블로그가 생성되어야 한다.
- **FR-011**: 블로그 홈은 블로그 제목, 소개, 카테고리 목록, 공개 글 목록(최신순, 한 페이지 20개)을 보여야 한다.
- **FR-012**: 블로그 주인은 블로그 제목, 소개, 대표 이미지, 댓글 허용 여부를 바꿀 수 있어야 한다.

**글**

- **FR-013**: 회원은 제목, 본문, 카테고리, 태그, 공개 범위를 지정해 글을 발행할 수 있어야 한다.
- **FR-014**: 본문은 Markdown으로 작성·저장한다. 작성 화면은 Markdown 입력과 서식 버튼 방식(WYSIWYG)을 오갈 수 있고 미리보기를 제공해야 한다. 독자에게는 Markdown을 변환한 결과가 보인다.
- **FR-015**: 공개 범위는 "공개", "보호(비밀번호)", "비공개(본인만)"를 지원해야 한다(보호 글 세부는 FR-062~063).
- **FR-016**: 글은 발행 전 임시저장할 수 있고, 임시저장 글은 주인에게만 보여야 한다.
- **FR-017**: 글 주인은 자기 글을 수정·삭제할 수 있어야 하며, 다른 사람은 할 수 없어야 한다.
- **FR-018**: 비공개·임시저장·삭제·숨김 처리된 글은 주인 외의 사람에게 "존재하지 않는 글"과 같은 응답을 주어야 하며, 어떤 목록·검색·피드·사이트맵에도 나오지 않아야 한다.
- **FR-019**: 글 상세는 제목, 본문, 작성자, 작성일, 카테고리, 태그, 조회수, 좋아요 수, 이전·다음 글을 보여야 한다.
- **FR-020**: 조회수는 같은 사용자(또는 같은 방문자)가 30분 안에 다시 열면 늘지 않아야 한다.
- **FR-021**: 본문과 댓글에 들어간 스크립트 등 위험한 내용은 다른 사용자 화면에서 실행되지 않도록 제거되어야 한다.
- **FR-022**: 블로그 주소는 `서비스 기본 도메인/블로그주소` 형식이어야 한다(예: `blog.java21.net/marco`는 marco의 블로그). 글 상세는 `서비스 기본 도메인/블로그주소/글번호` 형식이다(예: `blog.java21.net/marco/123`).

**카테고리와 태그**

- **FR-023**: 블로그 주인은 카테고리를 만들고, 이름을 바꾸고, 순서를 바꾸고, 삭제할 수 있어야 한다. 카테고리는 상위·하위 2단계까지 가능하다.
- **FR-024**: 카테고리를 삭제하면 소속 글은 "미분류"로 옮겨져야 한다.
- **FR-025**: 글 하나에 태그는 최대 10개이며, 태그는 서비스 전체에서 공유된다.
- **FR-026**: 방문자는 블로그 안의 카테고리별·태그별 글 목록과 서비스 전체의 태그별 글 목록을 볼 수 있어야 한다.

**댓글**

- **FR-027**: 로그인한 회원은 공개 글에 댓글을 달 수 있어야 하며, 댓글에는 답글을 한 단계까지 달 수 있다.
- **FR-028**: 댓글 작성자는 자기 댓글을 수정·삭제할 수 있고, 글 주인은 자기 글의 모든 댓글을 삭제할 수 있어야 한다.
- **FR-029**: 블로그 주인이 댓글을 막아둔 블로그에는 댓글을 달 수 없어야 한다.

**좋아요, 구독, 알림**

- **FR-030**: 로그인한 회원은 글마다 좋아요를 한 번 누르고 취소할 수 있어야 한다.
- **FR-031**: 로그인한 회원은 다른 사람의 블로그를 구독·취소할 수 있어야 하며, 자기 블로그는 구독할 수 없다.
- **FR-032**: 회원은 구독한 블로그들의 공개 글을 최신순으로 모아 보는 구독 피드를 볼 수 있어야 한다.
- **FR-033**: 회원은 내 글에 달린 새 댓글과 새 구독자에 대한 알림 목록을 볼 수 있어야 한다.

**둘러보기, 검색, 노출**

- **FR-034**: 메인 페이지는 서비스 전체의 최신 공개 글과 최근 7일 인기 글(좋아요와 조회수 기준)을 보여야 한다.
- **FR-035**: 방문자는 키워드로 서비스 전체 공개 글을 검색할 수 있어야 하며, 제목·본문·태그가 검색 대상이다.
- **FR-036**: 공개 페이지(메인, 블로그 홈, 글 상세, 목록)는 스크립트를 실행하지 않는 클라이언트가 요청해도 본문과 페이지 제목·요약 설명·공유용 미리보기 정보를 포함해야 한다.
- **FR-037**: 서비스는 공개 글 목록을 담은 사이트맵과 검색 엔진 접근 규칙(robots)을 제공해야 한다. 블로그 피드는 FR-044~048을 따른다.

**이미지**

- **FR-038**: 회원은 jpg, png, gif, webp 형식의 10MB 이하 이미지를 올려 글에 넣을 수 있어야 한다.
- **FR-039**: 올린 파일은 내용이 실제 이미지인지 확인되어야 하며, 원래 파일 이름은 저장 위치에 그대로 쓰지 않는다.
- **FR-071**: 에디터로 올린 이미지는 먼저 임시 보관 상태가 되고, 그 이미지가 들어간 글이 저장(임시저장 포함)되거나 발행될 때 정식으로 등록되어야 한다. 이미지 주소는 임시 보관에서 정식 등록으로 바뀌어도 그대로여야 한다.
- **FR-072**: 업로드 후 24시간 안에 어떤 글에도 등록되지 않은 임시 이미지는 자동으로 삭제되어야 한다.
- **FR-073**: 글을 수정해 본문에서 빠진 이미지와 영구 삭제된 글의 이미지는 정리 대상이 되어 자동으로 삭제되어야 한다.
- **FR-074**: 첨부 파일이 저장되는 위치(정식 보관 위치, 임시 보관 위치), 임시 보관 기간, 최대 파일 크기, 회원별 임시 보관 한도(기본 200MB)는 운영자가 서비스 설정으로 바꿀 수 있어야 한다. 한도를 넘는 업로드는 이유와 함께 거부한다.

**신고와 운영**

- **FR-040**: 로그인한 회원은 다른 사람의 글이나 댓글을 정해진 사유 중 하나로 신고할 수 있어야 한다.
- **FR-041**: 관리자는 신고 목록을 보고 콘텐츠를 숨기거나 신고를 기각할 수 있어야 한다.
- **FR-042**: 관리자는 사용자를 정지·해제할 수 있어야 하며, 정지된 사용자는 로그인할 수 없고 그 블로그는 "이용이 제한된 블로그"로 안내되어야 한다.
- **FR-043**: 관리 기능은 관리자 권한이 있는 계정만 쓸 수 있어야 한다.

**블로그 피드 (RSS·Atom)**

- **FR-044**: 블로그마다 RSS 2.0 피드와 Atom 1.0 피드를 제공해야 한다(예: `blog.java21.net/marco/rss`, `blog.java21.net/marco/atom`).
- **FR-045**: 카테고리별 피드를 제공해야 한다.
- **FR-046**: 블로그 주인은 피드에 담을 글 수(10·20·30·50, 기본 20)와 공개 형태(전문·요약, 기본 전문)를 정할 수 있어야 한다.
- **FR-047**: 피드에는 "공개 노출 가능" 글만 담고, 보호 글은 제목과 링크만 담는다.
- **FR-048**: 블로그 홈과 글 상세 페이지는 피드 자동 발견 정보를 포함해야 한다. 피드는 표준 검증기에서 오류 없이 통과해야 한다.

**트랙백**

- **FR-049**: 공개 글마다 고유 트랙백 주소가 있어야 하며, 글 상세에 표시해야 한다.
- **FR-050**: 시스템은 표준 TrackBack 핑(보낸 글 주소 필수, 제목·요약·블로그 이름 선택)을 받아 저장하고, 표준 형식의 성공·실패 응답을 돌려줘야 한다.
- **FR-051**: 받은 트랙백은 글 상세에 최신순으로 제목·요약(최대 255자)·블로그 이름·링크·받은 시각을 표시해야 한다.
- **FR-052**: 회원은 글을 발행하거나 수정할 때 트랙백을 보낼 외부 주소를 하나 이상 입력할 수 있고, 시스템은 표준 핑을 보내고 주소별 결과(성공·실패와 이유)를 기록해 보여줘야 한다. 서비스 안의 다른 블로그 글 주소도 같은 방식으로 동작해야 한다.
- **FR-053**: 블로그 주인은 블로그 단위로 트랙백 받기를 켜고 끌 수 있고(기본 켜짐), 받은 트랙백을 삭제할 수 있어야 한다.
- **FR-054**: 트랙백 스팸을 막기 위해 같은 출처에서 오는 핑 횟수를 제한하고, 같은 글에 같은 주소의 트랙백은 하나만 저장해야 한다. 관리자 신고 대상에 트랙백도 포함한다.
- **FR-055**: 비공개·보호·임시저장·삭제·숨김 글과 트랙백을 꺼둔 블로그의 글은 핑을 거부해야 한다.

**방명록**

- **FR-056**: 블로그마다 방명록이 있고, 로그인한 회원은 글을 남길 수 있어야 한다. 비회원 허용 여부는 FR-066 설정을 따른다.
- **FR-057**: 방명록 글은 비밀글로 쓸 수 있고, 비밀글은 블로그 주인과 작성자만 내용을 볼 수 있어야 한다.
- **FR-058**: 블로그 주인은 방명록 글에 답글을 달고, 어떤 방명록 글이든 삭제할 수 있어야 한다. 블로그 단위로 방명록을 켜고 끌 수 있어야 한다(기본 켜짐).

**블로그 꾸미기와 탐색 도구**

- **FR-059**: 블로그 주인은 글을 공지로 지정할 수 있고, 공지는 블로그 홈 목록 위에 따로 표시되며 공지 목록 화면이 있어야 한다.
- **FR-060**: 블로그 주인은 사이드바 항목(프로필, 카테고리, 최근 글, 최근 댓글, 인기 글, 태그 목록, 월별 보관함, 방문자 수, 검색, 피드 링크)을 켜고 끄고 순서를 바꿀 수 있어야 한다.
- **FR-061**: 블로그는 월별 보관함(연·월별 공개 글 수와 목록), 블로그 내 검색, 태그 목록(글 수가 많을수록 강조) 화면을 제공해야 한다.
- **FR-062**: 보호 글은 맞는 비밀번호를 입력한 방문자에게만 본문을 보여야 하며, 목록·검색·피드에는 제목만 노출되어야 한다. 비밀번호는 원문으로 저장하지 않는다.
- **FR-063**: 같은 방문자가 보호 글 비밀번호를 5회 연속 틀리면 10분간 시도를 막아야 한다.
- **FR-064**: 회원은 발행 시각을 미래로 지정해 예약 발행할 수 있고, 예약 시각이 되면 1분 이내에 자동으로 발행되어야 한다. 예약 글은 그 전까지 주인에게만 보인다.
- **FR-065**: 댓글 작성자는 비밀 댓글을 쓸 수 있고, 비밀 댓글은 글 주인과 작성자만 내용을 볼 수 있어야 한다.
- **FR-066**: 블로그 주인이 허용한 경우(기본 꺼짐) 로그인하지 않은 방문자도 이름·비밀번호로 댓글과 방명록을 쓸 수 있고, 같은 비밀번호로만 수정·삭제할 수 있어야 한다. 비회원 글에는 비회원임이 표시된다.
- **FR-067**: 블로그별 방문자 수(오늘, 어제, 전체)를 집계하며, 같은 방문자는 하루 한 번만 센다. 블로그 주인은 최근 30일 일별 방문자 수를 볼 수 있어야 한다.
- **FR-068**: 글 상세는 같은 블로그에서 카테고리·태그가 겹치는 관련 글을 최대 5편 보여야 한다.
- **FR-069**: 글 상세는 주소 복사와 주요 SNS(카카오톡, X, 페이스북) 공유 수단을 제공하고, 공유 미리보기를 위한 정보(제목, 요약, 대표 이미지)를 포함해야 한다.
- **FR-070**: 글 상세 주소(퍼머링크)는 글 제목을 바꿔도 변하지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **회원(User)**: 이메일, 닉네임, 소개, 프로필 이미지, 권한(일반/관리자), 상태(정상/정지/탈퇴). 블로그 1개를 가진다.
- **블로그(Blog)**: 블로그 주소, 제목, 소개, 대표 이미지, 댓글 허용 여부. 회원 1명에 속한다.
- **카테고리(Category)**: 이름, 순서, 상위 카테고리. 블로그에 속한다.
- **글(Post)**: 제목, 본문, 요약, 대표 이미지, 공개 범위, 상태(임시저장/발행/삭제/숨김), 조회수, 좋아요 수, 댓글 수, 발행 시각. 블로그와 카테고리에 속하고 태그 여러 개를 가진다.
- **태그(Tag)**: 이름. 여러 글이 공유한다.
- **댓글(Comment)**: 내용, 작성자, 상위 댓글, 상태. 글에 속한다.
- **좋아요(Like)**: 회원과 글의 관계. 회원·글 쌍마다 하나.
- **구독(Subscription)**: 회원과 블로그의 관계.
- **알림(Notification)**: 받는 회원, 종류, 관련 대상, 읽음 여부.
- **신고(Report)**: 신고자, 대상(글 또는 댓글), 사유, 처리 상태.
- **이미지(Media)**: 올린 회원, 저장 이름, 형식, 크기, 사용된 글, 상태(임시/등록/정리 대상), 업로드 시각.
- **로그인 연장 자격(Refresh credential)**: 회원, 만료 시각, 무효 여부. 로그아웃 시 무효화.
- **트랙백(Trackback)**: 받은 글, 보낸 쪽 글 주소, 제목, 요약, 블로그 이름, 보낸 곳 정보, 받은 시각.
- **보낸 트랙백 기록(Trackback ping log)**: 글, 대상 주소, 결과, 실패 이유, 시각.
- **방명록 글(Guestbook entry)**: 블로그, 작성자(회원 또는 비회원 이름), 내용, 비밀 여부, 상위 글(주인 답글).
- **블로그 설정(Blog settings)**: 피드 글 수·형태, 트랙백·방명록·비회원 댓글 허용, 사이드바 항목과 순서.
- **방문 집계(Visit stat)**: 블로그, 날짜, 방문자 수.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 사용자가 가입부터 첫 글 발행까지 3분 안에 마칠 수 있다.
- **SC-002**: 방문자는 글 상세 페이지를 열고 1초 안에 본문을 읽기 시작할 수 있다(일반 광대역 환경, 95% 요청 기준).
- **SC-003**: 회원 1만 명, 글 10만 편, 동시 접속 200명 상황에서 SC-002를 만족한다.
- **SC-004**: 비공개·삭제·숨김 글이 다른 사람에게 노출되는 경우가 0건이다(모든 목록·검색·피드·사이트맵·RSS 점검 기준).
- **SC-005**: 공개 글의 100%가 스크립트 없이 요청했을 때 제목과 본문을 포함한다.
- **SC-006**: 로그인한 사용자는 4시간 이내 활동 동안 다시 로그인하라는 요청을 받지 않는다.
- **SC-007**: 검색 결과는 95%의 경우 2초 안에 표시된다.

- **SC-008**: 모든 블로그 피드가 W3C 피드 검증기에서 오류 0건으로 통과한다.
- **SC-009**: 다른 블로그 서비스에서 보낸 표준 트랙백 핑의 95% 이상이 정상 저장되고, 이 서비스에서 보낸 트랙백은 대상이 표준을 따를 때 95% 이상 성공한다.
- **SC-010**: 예약 글은 예약 시각으로부터 1분 이내에 발행된다.

## Assumptions

- 대상 사용자는 한국어 사용자이며 서비스 언어는 한국어 하나다. 시간은 한국 시간으로 표시한다.
- 회원 1명당 블로그는 1개다. 여러 블로그 운영은 범위 밖이다.
- 소셜 로그인, 비밀번호 재설정 메일, 스킨/HTML·CSS 직접 편집, 광고·수익화, 상세 유입 경로 통계, 모바일 앱, 실시간 알림, 외부 블로그 글 가져오기(이전), 핑백(Pingback)은 이번 범위 밖이다.
- 블로그 고유 기능은 표준을 따른다: 피드는 RSS 2.0과 Atom 1.0(RFC 4287), 트랙백은 TrackBack 1.2 규격.
- 로그인 연장 자격의 4시간은 마지막 발급 시점부터 계산하며, 연장할 때마다 새로 발급되는 슬라이딩 방식은 쓰지 않는다(사용자가 4시간마다 한 번 다시 로그인).
- 화면은 모바일(폭 360px)부터 데스크톱까지 대응한다.
- 이메일 소유 확인(인증 메일)은 이번 범위 밖이며, 가입 즉시 이용할 수 있다.
- 첫 관리자 계정은 운영자가 직접 지정한다.
