# Feature Specification: 외부 블로그 RSS 수집과 주제 자동 분류

**Feature Branch**: `007-external-feeds`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "외부 RSS는 관리자가 직접 등록할 수도 있고, 사용자가 등록 신청하면 관리자 승인으로 반영된다. 우리 블로그 시스템에서 쓴 글이 아니더라도 RSS를 등록해 두면 외부 블로그 글도 수집해서 포털에서 카테고리(주제)별로 나눠 보여준다. 글을 보고 주제를 나누는 기술이 필요하다."

> 새 요구사항은 FR-109부터다. 포털(003)의 주제·노출 규칙과 관리자 콘솔(006)을 사용한다.

## 기본 원칙

- **원문은 원래 블로그에 있다.** 포털에는 제목, 요약(최대 200자), 대표 이미지 썸네일, 블로그 이름, 원문 링크만 보여주고, 본문 전체를 옮겨 싣지 않는다. 카드를 누르면 원래 블로그로 이동한다.
- **등록 경로는 두 가지다.** (1) 운영자가 관리자 콘솔에서 직접 등록, (2) 회원이 등록 신청 → 운영자 승인. 어느 경로든 운영자가 최종 반영한다.
- **주인의 동의가 없는 피드는 더 보수적으로 다룬다.** 운영자가 직접 등록했거나 소유 인증을 하지 않은 피드의 글은 썸네일 없이 제목·요약만 노출하고, 블로그 주인은 언제든 소유를 인증해 넘겨받거나(claim) 삭제를 요청할 수 있다.
- **분류는 단계적으로.** 처음부터 자체 알고리즘을 만들지 않는다. 블로그 기본 주제 + 피드 안의 카테고리·태그 규칙으로 시작하고, 자동 분류는 정확도를 측정할 수 있는 형태로 붙인다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 외부 블로그 등록: 회원 신청과 운영자 직접 등록 (Priority: P1)

외부 블로그는 두 경로로 들어온다. 회원은 RSS 주소로 등록을 신청하고(자기 블로그라면 소유 인증을 함께 할 수 있다), 운영자가 신청 목록에서 승인하면 수집이 시작된다. 운영자는 신청 없이 관리자 콘솔에서 직접 RSS를 등록할 수도 있다.

**Why this priority**: 수집 대상이 정해져야 나머지가 동작한다. 소유 인증과 승인은 저작권·스팸 문제를 막는 첫 관문이다.

**Independent Test**: (신청 경로) 회원이 RSS 주소로 신청 → 관리자 콘솔 신청 목록에 나타남 → 운영자 승인 → "수집 중". (직접 경로) 운영자가 콘솔에서 RSS 주소·기본 주제·등록 근거 입력 → 바로 "수집 중". 두 경우 모두 포털에 글이 나오는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 외부 블로그 주소나 RSS 주소를 입력하면, **Then** 시스템이 RSS(또는 Atom)를 찾아 블로그 이름과 최근 글 3편을 미리 보여준다.
2. **Given** 미리보기 확인 후, **When** 회원이 등록을 진행하면, **Then** 고유 인증 코드가 발급되고, 코드를 외부 블로그의 새 글·소개란 중 한 곳에 넣으라는 안내가 나온다.
3. **Given** 인증 코드를 넣은 회원, **When** "인증 확인"을 누르면, **Then** 시스템이 피드나 블로그 페이지에서 코드를 찾아 인증을 완료한다. 찾지 못하면 이유를 알려준다.
4. **Given** 회원, **When** 소유 인증을 하거나(자기 블로그) 건너뛰고(추천하는 다른 블로그) 기본 주제를 골라 신청하면, **Then** 운영자 승인 대기 상태가 되고 신청 목록에 소유 인증 여부가 표시된다.
5. **Given** 이미 등록되었거나 신청 중인 외부 블로그, **When** 또 신청하려 하면, **Then** 거부되고 이미 등록되어 있다고 안내된다(소유 인증으로 넘겨받기는 가능).
6. **Given** 운영자, **When** 신청 목록에서 승인하거나 사유와 함께 거절하면, **Then** 승인은 수집을 시작하고, 거절은 신청자에게 사유가 알려진다.
7. **Given** 운영자, **When** 관리자 콘솔에서 RSS 주소, 기본 주제, 등록 근거(예: "피드 공개 배포", "주인 허락 메일")를 입력해 직접 등록하면, **Then** 승인 절차 없이 바로 수집이 시작된다.
8. **Given** 소유 인증 없이 등록된 외부 블로그의 실제 주인, **When** 회원 가입 후 소유 인증을 하면, **Then** 그 블로그의 관리 권한(주제 수정, 해제, 삭제)을 넘겨받고 썸네일 노출이 켜진다.

### User Story 2 - 외부 글이 포털에 주제별로 나온다 (Priority: P2)

승인된 외부 블로그의 새 글은 주기적으로 수집되어 주제가 정해지고, 포털의 주제 페이지와 최신 글에 내부 글과 함께(외부 글 표시와 함께) 나온다.

**Why this priority**: 사용자가 원하는 핵심 가치다. 분류 정확도는 3번 스토리에서 끌어올린다.

**Independent Test**: 승인된 외부 블로그(기본 주제 "IT 인터넷")에 새 글 발행 → 수집 주기 안에 포털 "IT 인터넷" 페이지에 카드가 나오고, 카드를 누르면 원래 블로그 글로 이동하는지 확인.

**Acceptance Scenarios**:

1. **Given** 승인된 외부 블로그에 새 글, **When** 다음 수집 주기가 지나면, **Then** 포털에 제목·요약(최대 200자)·썸네일(소유 인증된 블로그만, FR-128)·블로그 이름·"외부" 표시가 있는 카드가 나온다.
2. **Given** 외부 글 카드, **When** 방문자가 누르면, **Then** 원래 블로그의 글 주소로 이동한다(새 탭).
3. **Given** 외부 글, **When** 주제가 정해질 때, **Then** 우선순위는 (1) 블로그 주인이 지정한 글별 주제, (2) 피드의 카테고리·태그가 매핑 규칙에 맞는 주제, (3) 자동 분류 결과(신뢰도가 기준 이상일 때), (4) 블로그 기본 주제 순이다.
4. **Given** 외부 블로그 원문이 삭제되어 링크가 열리지 않는 글, **When** 정기 점검에서 발견되면, **Then** 포털에서 내린다.
5. **Given** 인기 점수, **When** 외부 글을 계산할 때, **Then** 우리 서비스에서 측정 가능한 신호(포털 카드 클릭 수)만 쓰며, 내부 글과 같은 점수 체계에서 공정하게 비교되도록 운영자가 가중치를 조정할 수 있다.

### User Story 3 - 주제 분류 개선과 검수 (Priority: P3)

블로그 주인은 수집된 자기 글의 주제를 직접 고칠 수 있고, 운영자는 자동 분류 신뢰도가 낮은 글을 검수 목록에서 확인해 주제를 정한다. 사람이 고친 결과는 분류 정확도 측정과 개선에 쓰인다.

**Why this priority**: 자동 분류는 틀릴 수 있으므로 사람이 바로잡는 경로가 필요하다.

**Independent Test**: 자동 분류 신뢰도가 기준 미만인 글이 검수 목록에 들어가는지 확인 → 운영자가 주제 지정 → 포털에 반영되고 분류 정확도 지표에 반영되는지 확인.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 수집된 내 글 목록에서 글의 주제를 바꾸면, **Then** 포털에 바로 반영되고 이후 자동 분류가 덮어쓰지 않는다.
2. **Given** 자동 분류 신뢰도가 기준 미만인 글, **When** 수집되면, **Then** 블로그 기본 주제로 임시 노출되고 운영자 검수 목록에 들어간다.
3. **Given** 운영자, **When** 검수 목록에서 주제를 확정하면, **Then** 포털에 반영된다.
4. **Given** 운영자, **When** 분류 현황을 보면, **Then** 최근 30일 사람이 확인한 글 기준 자동 분류 정확도, 주제별 분포, 검수 대기 수가 보인다.
5. **Given** 운영자, **When** 피드 카테고리·태그 → 주제 매핑 규칙(예: 태그 "spring" → IT 인터넷)을 추가하면, **Then** 이후 수집되는 글에 적용된다.

### User Story 4 - 등록 해제와 운영 (Priority: P4)

블로그 주인은 언제든 등록을 해제하고 수집된 글을 모두 지울 수 있다. 운영자는 외부 블로그를 일시 중지·차단하고, 원문 저작권자의 삭제 요청을 처리한다.

**Why this priority**: 남의 콘텐츠를 다루는 기능에 반드시 필요한 탈출구다.

**Independent Test**: 블로그 주인이 등록 해제 + "수집된 글 삭제" 선택 → 포털에서 해당 블로그 글이 모두 사라지는지 확인.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 등록을 해제하면, **Then** 수집이 즉시 멈추고, "수집된 글도 삭제"를 고르면 포털에서 모두 사라진다.
2. **Given** 운영자, **When** 외부 블로그를 일시 중지하거나 차단하면, **Then** 수집이 멈추고 차단 시 포털에서 모두 내린다.
3. **Given** 등록하지 않은 원문 저작권자, **When** 회원이면 신고 버튼으로, 회원이 아니면 권리 침해 신고 양식(005 FR-040)으로 삭제를 요청하면, **Then** 운영자가 확인 후 해당 글 또는 블로그 전체를 내릴 수 있다.
4. **Given** 피드가 연속으로 실패(접속 불가, 형식 오류)하는 외부 블로그, **When** 7일 연속 실패하면, **Then** 수집이 자동으로 중지되고 주인에게 알림(002 FR-033)이 간다.

---

### Edge Cases

- 피드가 본문 전체를 주더라도 포털에는 요약 200자만 저장·노출한다. 요약은 HTML 태그를 제거한 텍스트다.
- 같은 글이 피드에서 수정되어 다시 오면 새 글로 만들지 않고 갱신한다(글 고유값·링크 기준).
- 피드에 수천 개의 과거 글이 있어도 등록 시점 기준 최근 30일 글까지만 가져온다.
- 외부 피드 주소가 내부망이나 서버 자신을 가리키면 등록을 거부한다(서버가 외부 주소에 요청을 보내므로 보안 위험).
- 성인·도박 등 부적절한 블로그는 승인 단계에서 거절하고, 승인 후 발견되면 차단한다.
- 우리 서비스(blog.java21.net) 블로그 주소는 외부 블로그로 등록할 수 없다.
- 외부 블로그를 신청·보유한 회원이 탈퇴하면 그 외부 블로그는 수집을 멈추고 수집된 글은 포털에서 내린다(FR-157).
- 외부 썸네일 이미지는 우리 서버가 원본을 그대로 옮겨 싣지 않고, 작은 크기로 줄여 캐시하거나 링크만 쓴다(계획 단계에서 결정).

## Requirements *(mandatory)*

### Functional Requirements

**등록과 인증**

- **FR-109**: 회원은 외부 블로그 주소 또는 RSS·Atom 주소를 입력해 등록을 신청할 수 있어야 하며, 시스템은 피드를 찾아 블로그 이름과 최근 글 3편을 미리 보여줘야 한다.
- **FR-110**: 소유 인증은 선택이다. 시스템이 발급한 인증 코드를 외부 블로그의 글 또는 소개란에 넣으면, 시스템이 피드나 블로그 페이지에서 코드를 확인해 인증한다. 인증 코드는 24시간 유효하다. 신청할 때 하지 않았더라도 나중에 인증할 수 있다.
- **FR-111**: 외부 블로그는 두 경로로 등록된다. (1) 회원 신청: 기본 주제(소분류)를 지정해 신청하면 운영자 승인 대기 상태가 되고, 운영자가 승인하면 수집이 시작된다. 운영자는 거절할 때 사유를 남기고, 승인·거절 결과를 신청자에게 알림(002 FR-033)으로 알린다. (2) 운영자 직접 등록: 관리자 콘솔에서 피드 주소, 기본 주제, 등록 근거를 입력하면 승인 없이 바로 수집이 시작된다. 모든 등록·승인·거절은 관리자 작업 기록(006 FR-106)에 남는다.
- **FR-128**: 소유 인증이 없는 외부 블로그(운영자 직접 등록, 미인증 신청)의 글은 포털에 썸네일 없이 제목·요약만 노출한다. 소유 인증이 완료되면 썸네일 노출이 켜진다.
- **FR-129**: 소유 인증이 없는 외부 블로그의 실제 주인은 회원으로 소유 인증을 해 등록을 넘겨받을 수 있고(이후 주제 수정·해제·삭제 가능), 회원이 아니어도 권리 침해 신고 양식(005 FR-040)으로 삭제를 요청할 수 있다. 각 외부 글 카드와 블로그 정보에 "삭제 요청" 링크를 둔다.
- **FR-112**: 하나의 외부 블로그(피드 주소 기준)는 한 번만 등록된다. 회원 1명당 신청·보유할 수 있는 외부 블로그는 최대 3개다(운영자 직접 등록은 제한 없음).

**수집**

- **FR-113**: 시스템은 승인된 외부 피드를 주기적으로(기본 30분, 운영자 설정) 수집해야 하며, 등록 시점에는 최근 30일 글까지만 가져온다.
- **FR-114**: 수집한 글은 제목, 요약(태그 제거 텍스트 최대 200자), 대표 이미지 주소, 원문 링크, 발행 시각, 피드의 카테고리·태그만 저장하고 본문 전체는 저장하지 않는다.
- **FR-115**: 같은 글(피드의 고유값 또는 원문 링크 기준)은 중복 저장하지 않고 갱신해야 한다.
- **FR-116**: 수집 요청은 피드 서버의 변경 여부 확인 기능을 활용해 바뀐 것이 없으면 내려받지 않아야 하며, 한 외부 블로그당 수집 주기보다 자주 요청하지 않는다. 서버가 외부 주소로 요청을 보낼 때 내부망 주소로의 요청은 차단한다.
- **FR-117**: 피드가 7일 연속 실패하면 자동 중지하고 블로그 주인(신청·소유 회원이 있으면)에게 알림(002 FR-033)으로 알려야 한다. 원문 링크가 열리지 않는 글은 주 1회 점검해 포털에서 내린다.

**주제 분류**

- **FR-118**: 외부 글의 주제는 다음 우선순위로 정한다: (1) 블로그 주인이 지정한 글별 주제, (2) 운영자가 정의한 매핑 규칙(피드 카테고리·태그 → 주제)에 맞는 주제, (3) 자동 분류 결과 중 신뢰도가 기준(기본 0.7) 이상인 것, (4) 블로그 기본 주제.
- **FR-119**: 자동 분류는 글의 제목·요약·피드 카테고리·태그를 입력으로 주제 소분류 하나와 신뢰도(0~1)를 내야 하며, 분류 방식은 교체할 수 있어야 한다. 신뢰도가 기준 미만이면 블로그 기본 주제로 노출하고 운영자 검수 목록에 넣는다.
- **FR-120**: 블로그 주인은 자기 외부 글의 주제를 바꿀 수 있고, 사람이 정한 주제는 자동 분류가 덮어쓰지 않는다.
- **FR-121**: 운영자는 매핑 규칙을 추가·수정·삭제하고, 검수 목록에서 주제를 확정할 수 있어야 한다.
- **FR-122**: 운영자는 최근 30일 사람이 확인한 글 기준 자동 분류 정확도, 주제별 분포, 검수 대기 수를 볼 수 있어야 한다.

**포털 노출**

- **FR-123**: 외부 글은 포털(메인 최신 글, 주제 페이지)에 "외부" 표시와 함께 내부 글과 섞여 나오며, 카드를 누르면 원문으로 새 탭에서 이동한다. 포털의 블로그당 노출 제한(003 FR-080)과 포털 제외(003 FR-093)를 똑같이 적용한다. 003 FR-088의 조건 중 글쓴이 가입 후 24시간과 본문 200자 조건은 적용하지 않으며(외부 글은 본문을 저장하지 않고 요약만 최대 200자), 블로그 포털 노출 설정(003 FR-089)은 내부 블로그 설정이므로 해당 없고 외부 블로그는 해제(FR-126)·일시 중지(FR-127)로 대신한다. 외부 글은 주제 자동 숨김 기준(003 FR-147)의 최근 30일 글 수에 포함한다. 인기 점수는 003 FR-086 대신 FR-124를 따른다.
- **FR-124**: 외부 글의 인기 점수는 포털 카드 클릭 수로 계산하며, 운영자는 내부 글 대비 가중치를 조정할 수 있어야 한다. 외부 글만 모아 보거나 숨기는 필터를 제공한다.
- **FR-125**: 외부 글은 우리 서비스의 검색(002)·RSS(002)·사이트맵에는 포함하지 않는다.

**해제와 운영**

- **FR-126**: 블로그 주인은 등록을 해제할 수 있고, 이때 수집된 글을 함께 삭제할지 고를 수 있어야 한다.
- **FR-127**: 운영자는 외부 블로그를 일시 중지·재개·차단할 수 있고, 차단하면 포털에서 그 블로그 글을 모두 내린다. 저작권자 삭제 요청은 신고(005 FR-040, 회원 신고 버튼 또는 비회원 권리 침해 신고 양식)로 받아 처리한다.
- **FR-157**: 외부 블로그를 신청·보유한 회원이 탈퇴하면(001 FR-009) 그 회원의 외부 블로그는 즉시 수집을 멈추고, 수집된 글은 포털에서 모두 내려야 한다. 같은 블로그의 실제 주인은 이후 소유 인증(FR-129)으로 새로 등록할 수 있다.

### Key Entities *(include if feature involves data)*

- **외부 블로그(External blog)**: 등록 경로(회원 신청/운영자 직접), 신청·소유 회원(없을 수 있음), 등록 근거, 소유 인증 여부, 블로그 이름, 사이트 주소, 피드 주소, 기본 주제, 상태(승인 대기/거절/수집 중/일시 중지/차단/해제), 인증 코드와 인증 시각, 마지막 수집 시각·결과, 연속 실패 수.
- **외부 글(External post)**: 외부 블로그, 피드 고유값, 원문 링크, 제목, 요약, 대표 이미지 주소, 발행 시각, 피드 카테고리·태그, 주제, 주제 결정 출처(주인/규칙/자동/기본), 자동 분류 신뢰도, 포털 클릭 수, 상태.
- **주제 매핑 규칙(Topic mapping rule)**: 키워드(피드 카테고리·태그), 대상 주제, 우선순위.
- **분류 검수(Classification review)**: 외부 글, 자동 분류 결과·신뢰도, 확정 주제, 검수한 관리자.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-018**: 승인된 외부 블로그의 새 글은 발행 후 1시간 안에 포털에 나타난다(수집 주기 30분 기준).
- **SC-019**: 사람이 확인한 외부 글 기준 최종 주제 정확도가 85% 이상이다(최근 30일).
- **SC-020**: 등록 해제·차단·삭제 요청 처리·회원 탈퇴 후 5분 안에 해당 글이 포털에서 사라진다(003 FR-090·SC-013과 같은 기준).
- **SC-021**: 외부 글 본문 전체가 서비스에 저장·노출되는 경우가 0건이다.

## Assumptions

- 001, 002, 003, 006이 구현되어 있다고 가정한다.
- 외부 블로그 등록은 회원에 속하며 회원의 블로그(001 FR-010, 회원당 여러 개)와 따로 센다. FR-112의 3개 한도도 회원 기준이다. 관리 화면은 회원의 어느 블로그 관리(`/{블로그주소}/manage/external-blogs`)에서 열어도 같은 목록이다.
- 외부 블로그 글은 포털 노출용 메타데이터만 다루며, 댓글·좋아요는 원래 블로그에서 한다.
- 자동 분류 방식은 계획 단계에서 정한다. 후보: (A) 키워드 사전 기반 규칙, (B) 외부 AI 모델 API로 주제 분류, (C) 직접 학습한 텍스트 분류 모델. 사람이 확정한 데이터가 쌓이기 전에는 (C)를 만들지 않는다.
- 서비스 약관에 "외부 블로그 등록 시 제목·요약·대표 이미지를 포털에 노출하는 데 동의"하는 조항을 넣는다(법률 검토는 운영 측에서 진행).
- 핑백·실시간 구독 프로토콜(WebSub)은 이번 범위 밖이다.
