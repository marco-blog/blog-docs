# Feature Specification: 관리 화면 (시스템 관리자 콘솔과 블로그 관리)

**Feature Branch**: `006-admin-consoles`

**Created**: 2026-10-06

**Status**: Draft

**Input**: User description: "전체 시스템 관리자의 관리자 페이지가 별도로 있어야 되고, 사용자(블로그 주인)의 관리자 페이지가 별도로 있어야 한다. 시스템 관리자가 글 분류(주제)를 미리 정해 두면 일반 사용자는 글을 쓸 때 선택한다."

> 이 스펙은 두 관리 화면의 구조(진입, 권한, 메뉴, 대시보드)와 공통 규칙을 정의한다. 각 메뉴의 세부 기능은 해당 기능 스펙의 FR을 따른다(표의 "출처"). 새 요구사항은 FR-096부터다.
>
> 구현 순서: 블로그 관리의 뼈대와 001 메뉴는 001과 함께, 시스템 관리자 콘솔의 뼈대와 주제·큐레이션 메뉴는 003과 함께 만든다. 나머지 메뉴는 각 기능 스펙을 구현할 때 채운다.

## 두 관리 화면 비교

| 구분 | 시스템 관리자 콘솔 | 블로그 관리 |
|---|---|---|
| 누가 | 서비스 운영자(관리자 권한 계정) | 모든 회원(자기 블로그만) |
| 주소 | `blog.java21.net/admin` | `blog.java21.net/manage` |
| 범위 | 서비스 전체(모든 회원, 모든 블로그, 포털) | 내 블로그 하나 |
| 진입 | 관리자 계정 로그인 후 상단 메뉴 "시스템 관리" | 로그인 후 상단 메뉴 "내 블로그 관리" |
| 화면 | 별도 레이아웃(관리자 전용 좌측 메뉴) | 별도 레이아웃(블로그 관리 좌측 메뉴) |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 블로그 주인이 내 블로그를 관리한다 (Priority: P1)

회원은 "내 블로그 관리"에 들어가 대시보드에서 오늘 방문자와 새 댓글을 확인하고, 좌측 메뉴에서 글·카테고리·댓글·블로그 설정을 관리한다.

**Why this priority**: 모든 회원이 매일 쓰는 화면이다. 001의 글·카테고리·댓글 관리가 여기에 모인다.

**Independent Test**: 회원으로 로그인 → `/manage` 진입 → 대시보드 수치 확인 → 글 관리에서 임시저장 글 찾기 → 카테고리 추가 → 설정에서 블로그 제목 변경 → 블로그 홈에 반영되는지 확인. 다른 회원의 블로그 관리 화면에는 들어갈 수 없는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** "내 블로그 관리"를 누르면, **Then** 자기 블로그의 관리 대시보드가 열린다.
2. **Given** 관리 대시보드, **When** 열면, **Then** 오늘·어제 방문자 수, 새 댓글·방명록(최근 7일), 최근 글 5편, 임시저장 글 수가 보인다(아직 구현되지 않은 스펙의 항목은 숨긴다).
3. **Given** 글 관리 메뉴, **When** 상태(전체·발행·임시저장·비공개·휴지통)와 카테고리로 거르고 제목으로 검색하면, **Then** 조건에 맞는 내 글만 보이고 여러 글을 골라 한꺼번에 공개 범위 변경·카테고리 이동·삭제할 수 있다.
4. **Given** 댓글 관리 메뉴, **When** 열면, **Then** 내 블로그 모든 글의 댓글이 최신순으로 보이고 바로 삭제할 수 있다.
5. **Given** 다른 회원, **When** 내 블로그의 관리 화면이나 관리 API에 접근하면, **Then** 거부된다.

---

### User Story 2 - 시스템 관리자가 서비스를 운영한다 (Priority: P2)

운영자는 "시스템 관리"에 들어가 대시보드에서 서비스 현황을 보고, 좌측 메뉴에서 주제(서비스 카테고리), 포털 추천, 회원, 신고, 서비스 설정을 관리한다.

**Why this priority**: 포털(003)의 주제와 추천, 운영(005)의 신고·정지가 모두 이 화면에서 이뤄진다.

**Independent Test**: 관리자 계정으로 `/admin` 진입 → 주제 소분류 추가 → 일반 회원 글쓰기 화면의 주제 선택에 새 소분류가 나오는지 확인. 일반 회원 계정으로 `/admin` 접근이 거부되는지 확인.

**Acceptance Scenarios**:

1. **Given** 관리자 계정, **When** "시스템 관리"를 누르면, **Then** 시스템 관리자 콘솔 대시보드가 열린다.
2. **Given** 일반 회원, **When** `/admin` 주소로 직접 들어가거나 관리자 API를 호출하면, **Then** "찾을 수 없음"과 같은 응답을 받는다(관리 화면의 존재를 드러내지 않음).
3. **Given** 콘솔 대시보드, **When** 열면, **Then** 오늘 가입자·발행 글·댓글 수, 전체 회원·블로그·글 수, 처리 대기 신고 수, 최근 7일 추이가 보인다.
4. **Given** 주제 관리 메뉴, **When** 대분류·소분류를 추가·이름 변경·순서 변경(끌어서 놓기)·숨김하면, **Then** 일반 회원의 글쓰기 화면 주제 선택과 포털 탭에 바로 반영된다.
5. **Given** 회원 관리 메뉴, **When** 이메일·닉네임·블로그 주소로 회원을 찾으면, **Then** 가입일·상태·글 수·신고 받은 수가 보이고 정지·해제할 수 있다.

---

### User Story 3 - 관리자 작업 기록과 권한 부여 (Priority: P3)

운영자의 모든 변경 작업은 기록으로 남고, 최고 관리자는 다른 회원에게 관리자 권한을 주거나 회수한다.

**Why this priority**: 운영 사고를 추적하고 책임을 분명히 하기 위한 장치다. 운영자가 한 명일 때는 필요성이 낮다.

**Independent Test**: 관리자가 회원 정지, 주제 숨김을 수행 → 작업 기록 메뉴에 누가·언제·무엇을·어떻게 바꿨는지 2건이 남는지 확인.

**Acceptance Scenarios**:

1. **Given** 관리자, **When** 정지, 주제 변경, 추천 지정, 포털 제외, 신고 처리, 설정 변경을 하면, **Then** 작업 기록에 관리자·시각·대상·변경 전후 값이 남는다.
2. **Given** 작업 기록, **When** 관리자가 기간·관리자·작업 종류로 거르면, **Then** 해당 기록만 보인다. 기록은 수정·삭제할 수 없다.
3. **Given** 최고 관리자, **When** 회원에게 관리자 권한을 주거나 회수하면, **Then** 그 회원의 다음 로그인(또는 토큰 갱신)부터 반영되고 작업 기록에 남는다.

---

### Edge Cases

- 관리자도 자기 블로그를 가진 회원이므로 "내 블로그 관리"와 "시스템 관리" 두 메뉴가 모두 보인다. 두 화면은 섞이지 않는다.
- 관리자 권한이 회수된 사람이 콘솔을 열어 둔 상태라면 다음 요청부터 거부된다.
- 최고 관리자는 최소 1명이 남아야 하며 마지막 최고 관리자의 권한은 회수할 수 없다.
- 관리자가 정지된 회원의 블로그 관리 화면에 대신 들어가는 기능은 없다(콘텐츠 조치는 콘솔의 신고·포털 제외·숨김으로만).
- 관리 화면은 검색 엔진에 노출되지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**공통**

- **FR-096**: 시스템 관리자 콘솔(`/admin`)과 블로그 관리(`/manage`)는 서로 다른 레이아웃·메뉴를 가진 별도 화면이어야 하며, 상단 메뉴에서 권한에 따라 각각 진입할 수 있어야 한다.
- **FR-097**: 블로그 관리는 로그인한 회원 본인의 블로그만 다루며, 다른 블로그의 관리 기능 요청은 거부해야 한다. 시스템 관리자 콘솔은 관리자 권한(일반 관리자, 최고 관리자)만 쓸 수 있고, 그 외 요청에는 존재를 드러내지 않는 응답을 줘야 한다.
- **FR-098**: 관리 화면은 검색 엔진 수집 대상에서 제외되어야 한다.

**블로그 관리 메뉴 (회원)**

- **FR-099**: 블로그 관리 메뉴는 아래로 구성하며, 아직 구현되지 않은 스펙의 메뉴는 숨긴다.

  | 메뉴 | 내용 | 출처 |
  |---|---|---|
  | 대시보드 | 방문자(오늘·어제), 새 댓글·방명록, 최근 글, 임시저장 수 | FR-100, 004 FR-067 |
  | 글 관리 | 상태·카테고리 필터, 검색, 일괄 공개 범위 변경·카테고리 이동·삭제, 휴지통 복구 | 001 FR-013~017, FR-084 |
  | 카테고리 관리 | 내 블로그 카테고리(2단계) 추가·이름·순서·삭제 | 001 FR-023~024 |
  | 댓글 관리 | 내 블로그 전체 댓글 목록, 삭제 | 001 FR-028 |
  | 방명록 관리 | 목록, 답글, 삭제 | 004 FR-056~058 |
  | 블로그 설정 | 제목·소개·대표 이미지, 댓글·방명록·비회원 글·트랙백 허용, 포털 노출, 기본 주제 | 001 FR-012, 003 FR-077·089, 004, 005 FR-053 |
  | 꾸미기 | 사이드바 항목·순서, 공지 | 004 FR-059~060 |
  | 피드 설정 | RSS 글 수·전문/요약 | 002 FR-046 |
  | 통계 | 최근 30일 일별 방문자, 글별 조회수 상위 | 004 FR-067 |
  | 받은 트랙백 | 목록, 삭제 | 005 FR-051·053 |

- **FR-100**: 블로그 관리 대시보드는 오늘·어제 방문자 수, 최근 7일 새 댓글·방명록 수와 최근 5건, 최근 글 5편, 임시저장 글 수를 보여야 한다.
- **FR-101**: 글 관리는 여러 글을 선택해 공개 범위 변경, 카테고리 이동, 삭제(휴지통)를 한 번에 할 수 있어야 한다.

**시스템 관리자 콘솔 메뉴 (운영자)**

- **FR-102**: 시스템 관리자 콘솔 메뉴는 아래로 구성하며, 아직 구현되지 않은 스펙의 메뉴는 숨긴다.

  | 메뉴 | 내용 | 출처 |
  |---|---|---|
  | 대시보드 | 오늘·누적 현황, 처리 대기 신고, 최근 7일 추이 | FR-103 |
  | 주제(서비스 카테고리) 관리 | 대분류·소분류 추가·이름·순서·숨김 | 003 FR-075·079 |
  | 포털 관리 | 추천 글 지정·기간·순서, 포털 제외 목록, 포털 설정값(가중치·노출 조건) | 003 FR-086·088·091~093 |
  | 회원 관리 | 검색, 상세(가입일·상태·글 수·신고 받은 수), 정지·해제 | 005 FR-042, FR-104 |
  | 콘텐츠 관리 | 글·댓글 검색, 숨김·복구 | 005 FR-041 |
  | 신고 관리 | 대기·처리 목록, 숨김·기각 | 005 FR-040~041 |
  | 외부 블로그 관리 | 등록 신청 승인·거절, 직접 등록, 일시 중지·차단, 주제 매핑 규칙, 분류 검수 | 007 FR-111·121·127 |
  | 예약어 관리 | 블로그 주소 예약어 조회·추가 | 001 FR-002 |
  | 서비스 설정 | 약관 버전, 첨부 파일 한도 표시(읽기 전용), 포털 조건값 | 001 FR-081, FR-074 |
  | 관리자 권한 | 관리자 목록, 권한 부여·회수(최고 관리자만) | FR-105 |
  | 작업 기록 | 관리자 작업 이력 조회 | FR-106 |

- **FR-103**: 콘솔 대시보드는 오늘 가입자·발행 글·댓글 수, 전체 회원·블로그·공개 글 수, 처리 대기 신고 수, 최근 7일 일별 가입·발행 추이를 보여야 한다. 수치는 최대 5분 지연을 허용한다.
- **FR-104**: 회원 관리는 이메일·닉네임·블로그 주소로 검색하고, 회원 상세(가입일, 상태, 글 수, 받은 신고 수, 최근 로그인 시각)를 보여야 한다. 관리자도 회원의 비밀번호나 비공개 글 본문은 볼 수 없다.
- **FR-105**: 관리자 권한은 "최고 관리자"와 "일반 관리자" 두 단계다. 관리자 권한 부여·회수는 최고 관리자만 할 수 있고, 최고 관리자는 최소 1명 남아야 한다. 첫 최고 관리자는 서비스 설치 시 운영 설정으로 지정한다.
- **FR-106**: 관리자의 모든 변경 작업(정지·해제, 주제 변경, 추천·포털 제외, 신고 처리, 콘텐츠 숨김, 설정 변경, 권한 변경)은 관리자·시각·대상·변경 전후 값으로 기록되어야 하며, 기록은 수정·삭제할 수 없고 1년간 보관한다.

### Key Entities *(include if feature involves data)*

- **관리자 권한(Admin role)**: 회원의 권한 단계(일반 회원 / 일반 관리자 / 최고 관리자). 001의 회원 권한을 세분화한다.
- **관리자 작업 기록(Admin audit log)**: 관리자, 작업 종류, 대상 종류·ID, 변경 전·후 값, 시각, 요청 IP.
- **예약어(Reserved handle)**: 블로그 주소로 쓸 수 없는 이름. 기본 목록 + 관리자 추가분.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-015**: 일반 회원 계정으로 시스템 관리자 기능에 접근이 성공한 경우가 0건이다(모든 관리자 API 권한 테스트 기준).
- **SC-016**: 회원은 "내 블로그 관리"에 들어가 원하는 글을 찾아 수정 화면까지 30초 안에 이동할 수 있다.
- **SC-017**: 관리자 변경 작업의 100%가 작업 기록에 남는다.

## Assumptions

- 두 관리 화면 모두 front 저장소 안의 화면이며 별도 앱이나 별도 도메인을 두지 않는다(헌법 원칙 II). 별도 도메인(예: admin.blog.java21.net)이 필요해지면 그때 결정한다.
- 시스템 관리자 콘솔은 데스크톱 화면 기준으로 만들고, 모바일은 조회 위주로 동작하면 된다. 블로그 관리는 모바일에서도 쓸 수 있어야 한다.
- 관리자 2단계 인증(OTP)은 이번 범위 밖이다.
- 001의 회원 권한(일반/관리자)은 이 스펙에서 일반 회원/일반 관리자/최고 관리자로 세분화한다.
