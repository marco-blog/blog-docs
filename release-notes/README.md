# 릴리스 노트

서비스(blog.java21.net) 단위로 버전마다 한 번 쓴다. 이 폴더는 **초안**이다. 이용자에게 보이는 원본은 관리자 콘솔의 "릴리스 노트" 메뉴(DB)이며, 관리자가 이 초안을 붙여 넣고 게시하면 포털 메인과 `/updates`에 나온다(독자 화면 003 FR-161~166, 관리자 작성·게시·수정본 006 FR-167·168). backend와 front는 함께 배포되므로 저장소별로 따로 쓰지 않는다.

## 파일 규칙
- 버전마다 4개 언어 파일을 만든다. 한국어가 기준이고, 나머지는 같은 내용의 번역이다.
  - `vX.Y.Z.md` (한국어, 기준)
  - `vX.Y.Z.en.md`, `vX.Y.Z.ja.md`, `vX.Y.Z.zh-CN.md`
- 각 파일 맨 위에 다른 언어 파일로 가는 링크를 둔다(README와 같은 방식).
- 4개 파일이 모두 있어야 릴리스한다. 하나라도 빠지면 그 버전은 배포하지 않는다.
- 버전 번호는 Semantic Versioning을 따르고, 같은 번호로 blog-backend와 blog-front에 Git 태그와 GitHub Release를 만든다. GitHub Release 본문에는 이 폴더의 한국어 파일 내용을 넣고 다른 언어 파일 링크를 붙인다.
- 읽는 사람은 서비스 이용자다. 내부 구현(클래스, 테이블 이름)은 쓰지 않고, 이용자가 보고 겪는 변화만 쓴다. 관련 스펙 번호(예: 001 FR-010)는 맨 아래 "관련 스펙"에만 적는다.
